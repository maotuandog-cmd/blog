## 1. 文档说明

### 1.1 编写原则

1. **只参考能力，不参考实现**：以业务功能清单为输入，不绑定现有项目类名、表结构、调用链或代码写法。  
2. **对标业界同类产品**：调度、拨测、远程执行、终端、采集等能力，参考 GitHub / 开源同类产品的产品形态与架构惯例完成设计。  
3. **可交付**：本文作为 Phase 2 开发的唯一需求基线；未列入范围的能力默认不做。

### 1.2 输入来源

| 来源 | 用法 |
|------|------|
| 现有引擎**功能清单**（拨测、作业、终端、发现、Trap/Syslog 等） | 划定 Hermes 要覆盖的能力边界 |
| GitHub 同类开源产品 | 借鉴职责拆分、任务模型、指标与安全惯例 |
| 运维场景约束 | 集群、机房、密钥、超时、审计、中文站点拨测等 |

### 1.3 非目标

- 不替代上游「任务编排 / 资产管控 / 告警中心」产品，Hermes 是**执行与采集节点**。  
- 不把 Hermes 做成通用 ChatOps / 多端 IM Agent；LLM 仅作为**可选浏览器执行能力**接入（见 §5.10）。  
- 不以「绕过第三方网站服务条款、突破未授权目标的反爬」为产品目标；类人浏览与反检测能力仅用于**授权目标**（自有系统拨测、签约巡检、合规数据采集）。  
- 不在需求阶段产出代码、接口实现或数据库 DDL。

## 2. 产品愿景与目标

### 2.1 一句话

Hermes 是部署在机房/边缘的**多协议运维执行引擎**：接收管控平台下发的作业与拨测任务，在本地完成远程执行、合成监控、诊断工具、可选终端与告警采集，并将结果、指标与审计回传。

### 2.2 建设目标

| 编号 | 目标 | 度量 |
|------|------|------|
| G1 | 能力覆盖：作业执行 + 合成拨测 + 基础诊断 | P0 用例全部通过验收 |
| G2 | 可靠调度：可集群、可超时回收、结果语义清晰 | 无「成功实失败」、无长期僵尸运行态 |
| G3 | 可观测：执行与拨测指标可被 Prometheus 拉取 | 核心指标齐全、带任务/资产标签 |
| G4 | 可扩展：新协议以插件方式接入 | 新增协议不改调度核心 |
| G5 | 安全默认：密钥外置、接口默认拒绝、会话可审计 | 安全基线清单勾选通过 |
| G6 | （可选）复杂页面可用自然语言驱动浏览并产出摘要 | 授权目标上完成旅程 + 结构化总结验收 |

## 3. 业界对标（设计参考）

以下产品**仅作能力与架构参考**，不要求协议兼容或代码复用。

### 3.1 对标矩阵

| 能力域 | 参考产品 | 可借鉴点 |
|--------|----------|----------|
| 作业编排 / 执行节点 | [Rundeck](https://github.com/rundeck/rundeck) 及 Ansible/Salt 执行插件生态 | Job = 步骤流；Node Executor 插件化；调度与执行分离；审计与 ACL |
| HTTP/网络探针 | [prometheus/blackbox_exporter](https://github.com/prometheus/blackbox_exporter)、[script_exporter](https://github.com/ricoberger/script_exporter) | Probe 模块化；`/metrics` + `/probe`；超时与成功失败二元语义清晰 |
| 轻量多协议探针 Agent | [probixel](https://github.com/kfalabs/probixel) | YAML 驱动；HTTP/TCP/DNS/SSH 等；隧道感知；配置热更新思路 |
| 浏览器合成监控 | [basecamp/upright](https://github.com/basecamp/upright)、[supercheck-io/supercheck](https://github.com/supercheck-io/supercheck)、[playwright-synthetic-monitoring](https://github.com/workadventure/playwright-synthetic-monitoring)、Checkly Playwright Check Suites | Playwright 旅程；步骤耗时；截图/录像；Prometheus 状态与时长；locale/多站点执行 |
| LLM 浏览器智能操作 | [Stagehand](https://github.com/browserbase/stagehand)、Browser Use、Playwright MCP 等 | 自然语言 `act/extract/observe`；确定性步骤与 AI 步骤混合；动作缓存；页面抽取与总结 |
| 类人浏览 / 反检测运行时 | Browserbase 类托管浏览器、自建 stealth/指纹/代理层 | 指纹与 TLS、住宅代理、人类化输入节奏、验证码协同；强反爬需「浏览器身份基础设施」而非仅改 UA |
| 远程执行与证据化结果 | [vssh](https://github.com/zeus-kim/vssh)、[mcp-ssh-fleet](https://github.com/inhuman/mcp-ssh-fleet) | 结构化结果（stdout/stderr/exit/duration）；清单白名单；超时与输出上限；能力分级（只读探测 vs 任意执行） |
| Web 远程终端 | Apache Guacamole / WebSSH 类产品 | 浏览器内 SSH/RDP；会话录制；文件挂载与传输 |
| Trap / Syslog | 业界 SNMP Trap Receiver、Syslog-ng/rsyslog 转发器模式 | 旁路长驻进程；解析 → 规范化 → 上报；与作业路径解耦 |

### 3.2 从对标中固化的设计约束

1. **调度与执行分离**：调度器只负责任务生命周期与配额；协议细节下沉到 Executor/Worker。  
2. **探针结果要可度量**：至少「是否成功 + 耗时 +（可选）状态码/步骤明细」。  
3. **浏览器拨测按「旅程」建模**：鉴权步骤与业务步骤分离；选择器/校验失败即失败；语言环境可配。  
4. **远程执行要有边界**：超时、输出大小上限、目标清单/凭证隔离。  
5. **采集旁路化**：Trap/Syslog 不走作业队列主路径，独立进程、独立背压。  
6. **浏览器能力分两层**：P0 确定性脚本拨测（稳定、便宜、可回归）；可选层 LLM 智能旅程（适配复杂/易变页面，成本与不确定性更高）。  
7. **反检测是基础设施问题**：仅靠脚本层「伪装」无法对抗强 Bot 管理；需指纹/代理/节奏/验证码策略分层，且仅用于授权目标。

## 4. 干系人与使用场景

### 4.1 干系人

| 角色 | 诉求 |
|------|------|
| 上游管控平台 | 下发即时/定时任务，查询结果与文件，拉取指标 |
| 运维工程师 | Web 终端、诊断工具、改密、查看会话与拨测失败截图 |
| 平台管理员 | 节点部署、并发配额、密钥、机房归属、集群扩缩 |
| 监控系统 | Prometheus 抓取、告警规则基于拨测/作业指标 |

### 4.2 核心场景（User Story）

| ID | 场景 | 验收要点 |
|----|------|----------|
| US-01 | 平台下发一条 SSH 作业，引擎在目标机执行命令并回传输出 | 成功/失败明确；超时可配置；输出可落盘 |
| US-02 | 定时 API 拨测业务 URL，采集可用性与耗时 | 支持鉴权步骤；指标可刮取 |
| US-03 | 仿真登录后访问业务页，校验关键元素出现 | 支持中文站点；失败保留截图/文本快照 |
| US-04 | 多节点部署时同一任务只被执行一次 | 原子认领；宕机任务可被回收重试 |
| US-05 | 工程师浏览器打开 Web 终端登录设备 | 会话可审计；（可选）录屏 |
| US-06 | 使用 Ping/Traceroute/SNMP Walk 做现场诊断 | 同步返回文本结果 |
| US-07 | 接收 SNMP Trap / Syslog 并上报平台 | 解析失败可重试；不影响作业执行 |
| US-08 | 对授权业务站点用自然语言描述复杂操作（登录→翻页→筛选→抽取），并输出结构化摘要 | 在目标清单内完成；产出证据（截图/步骤）+ 总结；可配置类人节奏与基础反检测 |

## 5. 功能需求

说明：优先级 **P0** 首期必须；**P1** 二期；**P2** 三期。每条需求含「能力描述」与「验收标准」，不规定实现类或语言 API。

### 5.1 任务与调度（核心平台能力）

| 需求 ID | 优先级 | 能力描述 | 验收标准 |
|---------|--------|----------|----------|
| F-SCHED-01 | P0 | 支持即时任务与定时任务两类执行触发 | 两类任务均可领取并执行 |
| F-SCHED-02 | P0 | 任务可包含多步骤（命令序列），按序执行 | 步骤结果可汇总；失败策略可配置（默认遇错即停） |
| F-SCHED-03 | P0 | 集群下任务原子认领，带租约（lease） | 两节点不会双跑同一任务；租约过期可回收 |
| F-SCHED-04 | P0 | 任务级超时；超时必须结束运行态并进入重试或失败 | 不存在永久 RUNNING |
| F-SCHED-05 | P0 | 可配置最大重试次数与重试间隔策略 | 达上限标记最终失败 |
| F-SCHED-06 | P0 | 按协议类型独立并发配额（尤其浏览器） | 超配额时任务等待或延迟认领，不拖垮主机 |
| F-SCHED-07 | P0 | 执行结果回写：状态、耗时、步骤输出、产物文件引用 | 上游可查询完整结果 |
| F-SCHED-08 | P0 | 执行审计：谁在何时对何资产执行了何任务 | 审计记录可检索 |
| F-SCHED-09 | P1 | 支持按机房/标签过滤本节点可执行任务 | 多机房部署互不抢错任务 |
| F-SCHED-10 | P1 | 任务取消 / 人工重跑 | 运行中可协作取消；终态可重入队 |

**状态机（需求级）：**

```
PENDING → CLAIMED → RUNNING → SUCCESS
                           ↘ FAILED
                           ↘ RETRY_WAIT → PENDING/CLAIMED
任意非终态 + 租约过期 → RETRY_WAIT 或 FAILED（达上限）
支持 CANCELLED
```

### 5.10 智能浏览器旅程（LLM，P1 正式能力）

> **已决策（2026-08-05）**：智能浏览 + 总结 = **P1**；LLM = **公有云 API**；反检测默认 = **L3**（与 L1/L2 一并纳入 P1）。  
> 仍与 P0「确定性 Browser 拨测」并列，不替换。对标 Stagehand / Browser Use + 增强反检测运行时。

| 需求 ID | 优先级 | 能力描述 | 验收标准 |
|---------|--------|----------|----------|
| F-LLM-01 | P1 | 支持「目标描述」驱动的多步页面操作（自然语言或结构化 goal） | 在授权样例站完成 ≥N 步动态旅程（登录/导航/表单/列表） |
| F-LLM-02 | P1 | 支持页面观察与信息抽取（表格/卡片/关键字段 → JSON Schema） | 抽取结果通过 schema 校验 |
| F-LLM-03 | P1 | 支持对浏览过程与抽取结果做**总结**（摘要、异常点、关键指标列表） | 输出固定模板：结论 / 证据引用 / 风险或异常 |
| F-LLM-04 | P1 | 确定性步骤与 LLM 步骤可混合编排 | 已知稳定步骤不走模型，降低成本与抖动 |
| F-LLM-05 | P1 | 默认对接**公有云 LLM API**（OpenAI 兼容等）；密钥仅环境变量；保留提供方抽象以便日后扩展 | 配置公有云 Key 即可跑通；日志不落完整 Prompt 中的密钥/Cookie |
| F-LLM-06 | P1 | 全程证据链：步骤轨迹、截图、模型决策摘要（脱敏） | 失败可复盘；敏感信息不入明文日志 |
| F-LLM-07 | P2 | 动作缓存 / 自愈：页面轻微改版时优先复用历史成功动作 | 同旅程二次执行可显著降 Token（有指标） |
| F-DET-01 | P1 | 基础反检测档：webdriver 特征收敛、常用指纹字段、UA/视口池 | 对「轻量 Bot 识别」样例站可通过 |
| F-DET-02 | P1 | 类人浏览档：键入节奏、点击偏移、滚动停顿、会话思考间隔可配 | 行为分布可配置区间，而非固定 sleep |
| F-DET-03 | P1 | **默认启用 L3**：代理池（住宅/机房分级）、TLS/指纹策略、验证码服务协同（可配） | 在授权强防护样例环境达到约定通过率；可按任务降级为 L2 |
| F-DET-04 | P0（策略） | **目标白名单 / 授权声明**强制：未授权域名拒绝执行智能浏览与增强反检测 | 缺授权配置时任务直接失败并审计 |
| F-DET-05 | P1 | 速率限制与并发隔离：智能浏览独立配额，避免打爆目标或本机 | 超限排队；有独立 Prometheus 指标 |

#### 5.10.1 能力分层（已决策：智能浏览默认跑满 L1+L2+L3）

| 层级 | P1 默认 | 适用 | 不保证 |
|------|---------|------|--------|
| L0 确定性拨测（F-BRW-* P0） | 独立能力 | SLA 监控、回归、固定选择器旅程 | 复杂动态页、频繁改版 |
| L1 LLM 智能操作 + 总结 | **启用** | 复杂后台、弱文档页面、需理解内容后操作与总结 | 100% 可重复路径 |
| L2 类人 + 基础反检测 | **启用** | 降低误判为机器人 | 单独对抗顶级 Bot 管理 |
| L3 增强反检测运行时 | **默认启用** | 授权场景提高可达率（代理/指纹/验证码） | 「必过任何反爬」；未授权用途 |

#### 5.10.2 与现有需求的关系

- **兼容**：调度、租约、配额、审计、结果回写模型不变；新增协议类型如 `BROWSER_AGENT` / `BROWSER_LLM`。  
- **不替代 P0**：可用性拨测仍以确定性脚本为主（成本低、可回归）。  
- **总结**：总结走公有云 LLM；输入为抽取 JSON + 证据元数据，默认脱敏后再出域。  
- **公有云约束**：页面原文/Cookie/账号密码不得无脱敏直传模型；F-SEC-06 强制出境策略与字段白名单。

#### 5.10.3 P1 智能浏览验收包（补充）

1. 授权样例站完成：自然语言目标 → 多步操作 → 结构化抽取 → 固定模板总结。  
2. 默认 L3 Profile 启动（含代理与指纹策略配置项）；同一任务可显式降级 L2。  
3. 公有云 API Key 仅环境变量；断网/鉴权失败时任务失败语义明确。  
4. 未在白名单的域名执行被拒绝并写审计。

## 5A. 专项分析：大模型复杂页面模拟 + 反爬 + 总结

### 5A.1 可行性结论

| 问题 | 结论 |
|------|------|
| 当前需求能否支持？ | **能**。浏览器 Executor 已是一等能力；扩展为「脚本拨测 + LLM 旅程」双模即可，不必改 Gateway/Bus 主架构。 |
| 能否做复杂页面模拟？ | **能（P1）**。对标 Stagehand/Browser Use：模型观察页面 → 决策动作 → 循环至目标；适合动态 DOM、缺稳定选择器的后台。 |
| 能否「类似人访问浏览并总结」？ | **能（P1）**。浏览过程用人机节奏增强；结束用 LLM 对抽取内容/截图说明做结构化总结。 |
| 能否支持反爬？ | **部分能**。L1/L2 可做；强反爬依赖 L3 浏览器身份与代理基础设施，且**仅限授权目标**。无法也不应承诺「绕过一切反爬」。 |

### 5A.2 推荐产品形态

```
任务目标（自然语言/JSON）
        │
        ▼
┌───────────────────┐     可选      ┌────────────────────┐
│ Planner / Agent   │◄── 公有云 LLM API ─►│ OpenAI 兼容等提供方 │
└─────────┬─────────┘               └────────────────────┘
          │ act / extract / observe
          ▼
┌───────────────────┐   指纹/代理/节奏   ┌────────────────────┐
│ Browser Runtime   │◄─────────────────►│ Anti-Detect Profile │
│ (Playwright/CDP)  │                   └────────────────────┘
└─────────┬─────────┘
          │ 证据 + 抽取 JSON
          ▼
┌───────────────────┐
│ Summarizer        │ → 结论摘要 + 异常点 + 引用证据
└───────────────────┘
```

### 5A.3 风险与约束

1. **合规**：未授权抓取、破解登录墙、对抗第三方反爬可能违法或违约 → 强制白名单与审计。  
2. **不确定性**：同目标多次路径可能不同 → 关键 SLA 仍用 L0；L1 适合巡检/辅助取数。  
3. **成本**：Token + 浏览器时长；需缓存、混合编排、独立配额。  
4. **对抗升级**：顶级 Bot 管理可持续检测自动化；客户端 stealth 边际递减。  
5. **幻觉**：总结必须绑定抽取证据，禁止无依据断言。

### 5A.4 分期建议

| 阶段 | 交付 |
|------|------|
| P0 | 仍只做确定性 Browser；预留协议扩展点与白名单模型 |
| P1 | F-LLM-01～06 + F-DET-01/02/**03**/04/05 + 总结模板 + 公有云 LLM；默认 L3 Profile |
| P2 | F-LLM-07 动作缓存自愈；反检测策略调优与更多样例基线 |

## 7. 技术架构选型（需求建议）

> 选型服务于需求，Phase 2 可按团队技能微调，但须满足第 5 章验收。

### 7.1 推荐：**Go 核心执行面 + Node 浏览器面**

| 层级 | 建议技术 | 理由（产品向） |
|------|----------|----------------|
| Gateway / Dispatcher / SSH / API / SQL / Collectors | Go | 长驻、高并发、单二进制分发，适合机房 Agent |
| Browser Executor | Node.js + Playwright（P0）；P1 增加 Agent 编排 + **公有云 LLM** | 合成监控与 LLM 浏览器生态一致 |
| Anti-Detect | P1 **默认 L3 Profile**（代理/指纹/验证码可配，可降级 L2） | 与脚本逻辑解耦 |
| Summarizer | 公有云 LLM，独立调用 | 输入限定为脱敏后的抽取结果+证据元数据 |
| Task Bus | **Redis Stream**（接口可替换为 NATS 等） | 原子消费、重试、背压；见 ADR-002 |
| 指标 | Prometheus 客户端库 | 与 Blackbox/Upright 运维习惯一致 |
| 终端（P1） | WebSocket + SSH库；图形可继续依赖 guacd | 降低首期复杂度 |

备选：全 Node（交付快，系统协议与常驻密度较弱）、全 Go（浏览器能力需评估 playwright-go/chromedp）。

### 7.2 部署形态

- 最小：单机 `gateway + workers`（含 browser worker）  
- 推荐：`gateway/dispatcher` 与 `browser-worker` 可分副本扩缩  
- Collectors、Terminal 可按需启用
