# 36 | 套路篇：怎么评估系统的网络性能？

原文：[time.geekbang.org/column/article/81497](https://time.geekbang.org/column/article/81497)

先弄清应用落在协议栈哪一层，再测那一层；低层性能封顶高层。要两台机器，**别用 localhost 测带宽**。

市面上说的「测带宽」多半测的是吞吐。Linux 吞吐一般小于带宽；交换机吞吐接近带宽。TCP/Web 更看并发和 QPS。

## 工具对照

| 层 | 关心什么 | 工具 |
|----|----------|------|
| 网络接口/网络层 | PPS，尤其 64B 小包 | 内核 **pktgen**（`modprobe pktgen`，经 `/proc/net/pktgen` 配）；也可用 hping3 |
| 传输层 | TCP/UDP 吞吐 | **iperf3** / netperf |
| HTTP | QPS、延迟分布 | ab、webbench；ab 本身可能成为瓶颈 |
| 带真实负载的应用 | 模拟用户 payload | **wrk**（LuaJIT）、TCPCopy、Jmeter、LoadRunner |

`iperf` 只说明系统网络吞吐没问题，**不能代替应用压测**。

## pktgen 要点

每 CPU 一个 `kpktgend_X` 线程。配 `count`、`pkt_size`、`dst`/`dst_mac` 后 `echo start > /proc/net/pktgen/pgctrl`。结果里看 PPS、Mb/s、errors。千兆交换机线速约 `1000Mbps / ((64+20)*8)` ≈ **1.5 Mpps**；普通 Linux 12 万 PPS 并不丢人，万兆+优化可到数百万，DPDK/XDP 可到千万。

## iperf3

服务端：`iperf3 -s -i 1 -p 10000`  
客户端：`iperf3 -c <ip> -b 1G -t 15 -P 2 -p 10000`（`-b` 是 iperf 自己发包的目标速率）

看 SUM 的 receiver Bandwidth。

## HTTP

```bash
ab -c 1000 -n 10000 http://目标/
wrk -c 1000 -t 2 http://目标/          # 通常比 ab 测出更高 QPS
wrk -c 1000 -t 2 -s auth.lua http://目标/
```

ab 的 Time per request 有两行：带调度的平均延迟 vs 单请求真实响应时间。工具本身性能会扭曲结果。
