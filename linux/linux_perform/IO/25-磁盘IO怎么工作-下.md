# 25 | Linux 磁盘 I/O 是怎么工作的（下）

原文：[time.geekbang.org/column/article/77511](https://time.geekbang.org/column/article/77511)

五个指标要一起看，再叠加读写比、随机/连续、请求大小。别单挑一个数。

| 指标 | 含义 | 注意 |
|------|------|------|
| 使用率 `%util` | 处理 I/O 的**时间**百分比 | 只看有没有 I/O，不看大小。**100% 仍可能接新请求**（盘能并行） |
| 饱和度 | 繁忙程度 | 100% 才接不了新请求；**iostat 没有这一列**，拿队列长度 / await 跟 fio 基准比 |
| IOPS | 每秒请求数 | 随机、小文件、数据库更看这个 |
| 吞吐量 | 每秒数据量 | 顺序、多媒体更看这个 |
| 响应时间 | 发出到完成 | `await`；随机 vs 顺序差很多 |

选型先用 **fio** 按应用真实模式测：块大小 512B～1MB，随机读/写、顺序读/写都跑。出事时拿这些当上限。

块层调度是 OS 的；盘控制器自己还有电梯调度，两层都有。

## 看盘：iostat

数据来自 `/proc/diskstats`。

```bash
iostat -d -x 1
```

| 列 | 对应 |
|----|------|
| `%util` | 使用率 |
| `r/s + w/s` | IOPS |
| `rkB/s + wkB/s` | 吞吐 |
| `r_await` / `w_await` | 读/写平均等待 |
| `rareq-sz` / `wareq-sz` | 平均请求大小 |
| `aqu-sz` | 平均队列长度 |
| `rrqm/s` `wrqm/s` | 合并次数 |

`r_await + w_await` 不是严格的「总平均响应」公式（两个平均不能直接加）。同间隔下看各自即可，总平均用 `await`。

## 看进程

```bash
pidstat -d 1     # kB_rd/s、kB_wr/s、取消写 kB_ccwr/s、iodelay
iotop            # 按 I/O 排序
```

`iotop` 第一行「进程请求合计」和第二行「盘上真实读写」经常对不上：缓存、Buffer、合并都会把请求吃掉或拼掉。

随机还是顺序：跟系统调用里读写的**相对偏移**，不是跟数组/链表这种内存结构。
