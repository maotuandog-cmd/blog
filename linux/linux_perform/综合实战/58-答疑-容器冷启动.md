# 58 | 答疑（六）：容器冷启动如何性能分析？

原文：[time.geekbang.org/column/article/89613](https://time.geekbang.org/column/article/89613)

综合案例篇收尾答疑。

## 1. 容器冷启动慢在哪

第 46 讲是 Cgroups 内存限制没被应用感知，分多了被 OOM。冷启动更细：时间花在哪几段。

Serverless 一次启动大致：事件触发 → 资源调度 → 镜像拉取 → 网络配置 → 启动应用。各段用链路跟踪计时，最慢那段再用应用监控或动态追踪往下钻。

常见加速：热点镜像缓存、网络资源预分配、复用预先建好的容器（warm pool）。

## 2. CPU 火焰图 vs 内存火焰图

图的格式一样，差在**采样事件**：

- on-CPU：默认 `cpu-cycles`，看谁在吃 CPU
- 内存：换成 `page-fault` 等内存管理事件，看分配/释放/缺页
- 还有 off-CPU：看阻塞在哪

```bash
perf record                 # on-CPU
perf record -e page-fault   # 内存缺页 → 内存火焰图
```

## 3. `perf probe` 失败

动态追踪要把地址变成函数名，内核装 debuginfo；应用两条路：

- 有调试包就装：Ubuntu `bash-dbgsym`，CentOS `debuginfo-install bash`
- 没有就自己编译加 `-g`

## 4. RED vs USE

- **USE**：资源的使用率、饱和度、错误数
- **RED**（Weave Cloud + Prometheus）：微服务的 Rate、Errors、Duration

资源用 USE，应用/微服务用 RED。

## 5. 内核函数看不懂

按**本机内核版本**查源码：[elixir.bootlin.com](https://elixir.bootlin.com)，选版本后搜函数名，定义可跳转。eBPF 先从 [BCC](https://github.com/iovisor/bcc) 短示例下手，再进内部。
