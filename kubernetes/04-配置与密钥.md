# 04 · 配置与密钥

> 承接 [[03-工作负载基础]]。官方：[ConfigMaps](https://kubernetes.io/docs/concepts/configuration/configmap/) · [Secrets](https://kubernetes.io/docs/concepts/configuration/secret/)

## 1. ConfigMap：非敏感配置

```bash
kubectl create configmap app-config \
  --from-literal=APP_ENV=prod \
  --from-literal=LOG_LEVEL=info

# 或 --from-file=./config.properties
kubectl get cm app-config -o yaml
```

注入方式：

| 方式 | 适用 |
|------|------|
| `envFrom.configMapRef` | 整份变环境变量 |
| `env.valueFrom.configMapKeyRef` | 单个键 |
| `volume.mount` | 挂成文件 |

```yaml
envFrom:
- configMapRef:
    name: app-config
# 或
volumeMounts:
- name: cfg
  mountPath: /etc/app
volumes:
- name: cfg
  configMap:
    name: app-config
```

## 2. Secret：敏感数据

默认仅 **base64**，不是加密保险箱。etcd 加密、外部密钥管理是进阶话题。

```bash
kubectl create secret generic app-secret \
  --from-literal=DB_PASSWORD='change-me'

kubectl get secret app-secret -o jsonpath='{.data.DB_PASSWORD}' | base64 -d; echo
```

挂载方式与 ConfigMap 类似：`secretKeyRef` / `secret` volume。  
`type: kubernetes.io/dockerconfigjson` 用于私有镜像拉取。

## 3. 更新注意

- 改 CM/Secret 后：**环境变量注入的 Pod 不会自动重载**，需滚动重启 Deployment。  
- 文件挂载多数可热更新（依赖 kubelet 同步），应用是否热读另说。

```bash
kubectl rollout restart deploy/nginx
```
