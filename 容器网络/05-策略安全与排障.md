# 05 · 策略、安全与排障

> 承接 [[03-Kubernetes网络模型与Service]]、[[04-CNI插件与南北向流量]]。  
> 深读：quant67 19–26（NetworkPolicy、加密、MTU、DSR、可观测、疑难手册）。

## 1. NetworkPolicy 能力边界

原生 `NetworkPolicy`：

- 选中 Pod（podSelector）+ 命名空间  
- 入站/出站规则：IP 块、其它 Pod、命名空间、端口  
- **默认「无策略 = 全开」**；有策略后行为取决于实现（常变为对选中 Pod 默认拒绝未允许流量）

注意：

1. **必须 CNI 支持**；Flannel 默认不管策略  
2. 策略基于 **IP/端口**；Pod 重建换 IP 后靠 selector 重算  
3. 主机网络 / 部分系统命名空间流量要单独想清楚  
4. Cilium 等可用 **CiliumNetworkPolicy** 做 L7/身份增强  

```bash
kubectl get networkpolicy -A
# 测试：在允许/拒绝两端用 curl，同时抓包或看 CNI flow
```

## 2. 加密与零信任（概念层）

| 手段 | 层 | 备注 |
|------|----|------|
| WireGuard / IPsec | 节点/Pod 覆盖层 | Calico/Cilium 可选透明加密 |
| mTLS | 应用/网格 | Service Mesh 或 sidecar |
| NetworkPolicy | L3/L4 | 不是加密 |

安全加固顺序建议：先 **默认拒绝 + 最小放行**，再谈加密与网格，避免一上来全套 Mesh。

## 3. 排障总原则

1. **先确认 Pod 已 Running、已分配 IP**（不是 Pending/调度失败）  
2. **分层**：应用 → DNS → Service → Pod IP → 节点路由/CNI → 物理网络  
3. **同节点 vs 跨节点**分开验证  
4. **直连 Pod IP** 与 **走 Service** 分开验证  
5. 改一条只验证一条；记录 `tcpdump` 在哪一侧看到包

## 5. 高频故障速查

| 现象 | 优先怀疑 | 先查什么 |
|------|----------|----------|
| 同节点通、跨节点不通 | overlay/路由/防火墙 | 节点路由、VXLAN 端口、云安全组 |
| Pod IP 通、Service 不通 | kube-proxy/eBPF LB | iptables KUBE-* / `ipvsadm` / cilium service |
| Service 通、域名不通 | CoreDNS / ndots / search | `nslookup`、CoreDNS 日志、`dnsPolicy` |
| DNS 偶发慢约 5s | conntrack 竞态、上游超时、ndots 双查询 | 搜「5 second DNS」类已知问题；查 conntrack |
| 新建连接失败、旧连接还好 | conntrack 表满 | `nf_conntrack_count/max` |
| 大包不通、小包通 | MTU / PMTUD 黑洞 | 隧道开销、`tracepath`、调低 Pod/接口 MTU |
| 外部源 IP 全变成节点 IP | NodePort/LB SNAT | `externalTrafficPolicy` |
| NetworkPolicy「全挂」 | 默认拒绝过严 / 未放行 DNS | 是否放行 kube-dns、标签是否匹配 |
| Pending 无 IP | 调度/资源/污点 | 先 `kubectl describe` Events，别先抓包 |

## 6. MTU 与隧道

VXLAN 等封装要吃字节（外层 IP+UDP+VXLAN 头）。  
宿主机 1500 时，Pod 侧常需 **更小 MTU**，否则大包分片/黑洞。

```bash
ip link show | rg -i 'mtu|flannel|vxlan|cilium|calico'
```

## 7. 建议的「最小验收」脚本思路

在任意测试命名空间：

1. 两 Pod 同节点：互 ping / curl Pod IP  
2. 两 Pod 异节点：同上  
3. 访问 ClusterIP Service  
4. 解析 Service DNS  
5.（可选）NodePort 从集群外访问  

每步失败就停在该层，不要跳着改。
