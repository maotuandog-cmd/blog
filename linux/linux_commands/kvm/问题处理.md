### 1 全新安装 Rocky 10.2 后,kickstart 的 %post 产物一件都没进目标系统

> 环境:Ubuntu 26.04 宿主机 / libvirt 12.0.0 / QEMU 10.2.1,ISO 为
> `Rocky-10.2-x86_64-minimal.iso`(卷标 `Rocky-10-2-x86_64-dvd`),
> 走 `LABEL=OEMDRV` 的 ISO 交付 kickstart,直接内核引导(`inst.stage2=hd:LABEL=...`)
>
> 现象:anaconda 的任务队列明明跑完了(串口能看到 "Running post-installation scripts"
> 和 "Complete!"),但 `%post` 写的 `/root/.ssh/authorized_keys`、`/etc/hostname`、
> 自定义 systemd 服务、`/var/log/anaconda/` **全都不在目标系统里**。
> 10-26 那次手工安装出来的模板,`authorized_keys` 也是装完(11:46)之后手工补的(11:52)。
>
> 结论:**不要假设 `%post` 生效**。全新安装后必须补一次离线修复(见第 2、3 条)。

诊断:

```bash
# 串口日志里确认安装器确实跑完了
grep -a "post-installation\|Complete!" /var/log/libvirt/<vm>-install.log

# 目标系统里查产物(挂盘后看)
ls /mnt/g/root/.ssh/ /mnt/g/etc/hostname
```

修法(离线挂盘补齐,宿主机没有 SELinux,只能手写 xattr):

```bash
virsh destroy <vm>
modprobe nbd max_part=16
qemu-nbd --connect=/dev/nbd0 /var/lib/libvirt/images/<vm>.qcow2
mkdir -p /mnt/g && mount /dev/nbd0p4 /mnt/g     # root 是 xfs,分区4

# 主机密钥:用 guest 自带的 ssh-keygen 生成(chroot 里跑,要能访问 /dev/urandom)
mount --bind /dev /mnt/g/dev && mount -t proc proc /mnt/g/proc
chroot /mnt/g /usr/bin/ssh-keygen -A
umount /mnt/g/proc; umount /mnt/g/dev

install -d -m 700 /mnt/g/root/.ssh
cat <pubkey> > /mnt/g/root/.ssh/authorized_keys && chmod 600 /mnt/g/root/.ssh/authorized_keys
echo <vmname> > /mnt/g/etc/hostname
sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin yes/' /mnt/g/etc/ssh/sshd_config

umount /mnt/g && qemu-nbd --disconnect /dev/nbd0 && virsh start <vm>
```

### 2 全新安装后能 ping 通但 SSH 报 Connection refused

> 看着像防火墙,其实是 sshd 根本起不来 —— **`/etc/ssh/ssh_host_*` 主机密钥没有**
> (第 1 条的 `%post` 没落地)。端口是 **CLOSED(被拒)** 不是被丢弃,
> 所以别往防火墙方向查。firewalld 默认 zone 在
> `firewall-offline-cmd --add-service=ssh` 跑过之前只放行 ssh 以外的端口。
>
> 另外缺 `sshd_key_t` 标签时 sshd 也读不到密钥,同样是 22 端口拒绝连接。

诊断:

```bash
# 宿主机上
nc -zv <ip> 22                 # refused = 服务没起来,不是被防火墙丢
# 虚机里
systemctl status sshd
ls -Z /etc/ssh/ssh_host_ed25519_key      # 必须是 sshd_key_t
```

修法:见第 1 条(生成主机密钥 + 手打标签)。宿主机没有 SELinux,
chroot 里的 `restorecon` 一定失败,只能用 python 写 xattr:

```bash
python3 - <<'PY'
import os
L={'/etc/ssh/ssh_host_ed25519_key':'sshd_key_t','/etc/ssh/ssh_host_ed25519_key.pub':'sshd_key_t',
   '/root/.ssh':'ssh_home_t','/root/.ssh/authorized_keys':'ssh_home_t',
   '/etc/hostname':'hostname_etc_t','/etc/machine-id':'machineid_t'}
for p,t in L.items():
    fp='/mnt/g'+p
    if os.path.lexists(fp):
        os.setxattr(fp,'security.selinux',('system_u:object_r:%s:s0\0'%t).encode())
PY
```

### 3 登录进去能看不能改,任何写入都报 Read-only file system

> 最坑的一个,迷惑性极强:SSH 通、firewalld 正常、`ls`/`cat` 都好,
> **唯独写不了任何文件**。
>
> 根因是两层:
> ① anaconda 的 **"Set file contexts"(SELinux 重打标签)步骤也没落地**(和 `%post` 一样),
>    安装期新建的文件留着安装环境的默认标签 **`root_t`**。
>    注意 `root_t` 是**打错了标签**,不是"未打标签",更隐蔽。
>    实测就 12 个:`/etc/fstab`、`/etc/crypttab`、`/etc/resolv.conf`、
>    `/etc/nvme/host{nqn,id}`、`/var/lib/dnf/history.sqlite*`、`/tmp`。
> ② 根分区是用 `ro` 挂的,**负责把它翻成 rw 的是 `systemd-remount-fs.service`**。
>    这服务跑在受限域里,SELinux 挡住它读 `root_t` 的 `/etc/fstab` →
>    `Permission denied` → 服务失败 → **根永远只读**。

诊断:

```bash
findmnt -no SOURCE,FSTYPE,OPTIONS /          # → /dev/vda4 xfs ro   ← 关键
systemctl status systemd-remount-fs.service   # → failed
journalctl -b -u systemd-remount-fs.service
#   Failed to open /etc/fstab: Permission denied
ls -Z /etc/fstab                              # → root_t,正确的是 etc_t
```

修法(在虚机里,用虚机自己的策略;宿主机没 SELinux,chroot 里 restorecon 一定失败):

```bash
mount -o remount,rw /            # XFS 日志干净的话直接就能翻
restorecon -RF -x /              # 修正根文件系统上的标签
restorecon -RF -x /boot          # /boot 是独立挂载点
systemctl restart systemd-remount-fs.service
```

离线修也可以(先 `virsh destroy` → qemu-nbd 挂载 → python `os.setxattr` 把
`/etc/fstab`、`/etc/crypttab` 打成 `etc_t`,`/etc/resolv.conf` 打成 `net_conf_t`)。

### 4 安装器跑了两遍,磁盘被第二次安装搅乱

> 安装完要从"安装态"切成"磁盘态",做法是 undefine 旧的 + define 新的。
> 如果 `destroy` 之后立刻 `undefine`,域还处在 `shutting off`,undefine 会失败;
> 紧接着 define 报 `already exists with uuid`,最后 `virsh start` 把
> **安装态**域又拉起来 → 安装器重跑一遍。
>
> 现象:安装日志里出现**第二次 `inst.stage2=...` 启动**。

```bash
# 错误写法
virsh destroy rocky10-2
virsh undefine rocky10-2      # 失败(域还在 shutting off)
virsh define disk.xml         # 失败:already exists with uuid
virsh start rocky10-2         # 把安装态域又拉起来了

# 正确写法:等域彻底消失再 undefine/define,并校验磁盘态 XML 里没有 <cmdline>
virsh destroy rocky10-2
for i in $(seq 1 60); do
    st=$(virsh domstate rocky10-2 2>/dev/null || echo "not found")
    [[ "$st" == "shut off" || "$st" == "not found" ]] && break
    sleep 1
done
virsh undefine rocky10-2
virsh define disk.xml
virsh dumpxml rocky10-2 | grep '<cmdline>' && echo "会重跑安装器!"
```

> 查日志时注意:一次启动里 `inst.stage2` 会出现在**两行**——内核的 `Command line:`
> 和 dracut 的 `Kernel command line:`,别数错。

### 5 重建之后 virt-manager(VMM)里看不到这台机器

> `virsh list --all` 里有、SSH 也通,但 VMM 列表里没有。
> 看 VMM 日志:`~/.cache/virt-manager/virt-manager.log`
>
> ```
> Error refreshing <vmmDomain name=rocky10-2> from events:
>   Domain not found: no domain with matching uuid '96a02716-...' (rocky10-2)
> ```
>
> 根因:**domain XML 里不写 `<uuid>`,libvirt 每次 define 都随机生成一个**。
> 第 4 条的 undefine+define 让同一台机器前后两个域 UUID 变了,
> 而 virt-manager 是**按 UUID 认域**的,就留下了悬空对象。

临时解决:VMM 里右键连接 → "断开连接" → 再双击连上(重新枚举)。

根治:给每台机器一个**稳定 UUID**,写进 XML:

```bash
stable_uuid() {
    local name=$1 h
    h=$(printf '%s' "$name" | md5sum | cut -c1-32)
    printf '%s-%s-%s-%s-%s' "${h:0:8}" "${h:8:4}" "${h:12:4}" "${h:16:4}" "${h:20:12}"
}
pick_uuid() {
    # local 的多个赋值是"先全部展开再依次赋值",
    # 不能写成 local name=$1 f="...$name..."(那样 $name 是外层空值),必须拆开
    local name=$1
    local f="$REG_DIR/.uuid-$name"
    mkdir -p "$REG_DIR"
    if [[ -s $f ]]; then cat "$f"; else
        local u; u=$(stable_uuid "$name"); echo "$u" > "$f"; echo "$u"
    fi
}
```

> libvirt **不允许**修改已存在域的 UUID(`virsh define` 报
> `domain 'x' already exists with uuid ...`),所以只能在建域时定好。

### 6 离线改 qcow2 的几个坑

> `qemu-nbd --connect` + mount 之后直接编辑目标系统时的注意事项。

```bash
# (1) machine-id 只能"换",不能删
#     删了 /etc/machine-id,systemd 生成不了 DHCP DUID,NetworkManager 不启动,
#     表现是能开机但拿不到 DHCP 地址,DHCP 租约里也看不到它的 MAC
printf '%s' "$(cat /proc/sys/kernel/random/uuid | tr -d '-')" > /mnt/g/etc/machine-id
chmod 0444 /mnt/g/etc/machine-id
ln -sf /etc/machine-id /mnt/g/var/lib/dbus/machine-id

# (2) 离线新建的文件没有 SELinux 标签(宿主机没 SELinux,chroot 里 restorecon 一定失败,
#     而且 || true 会把失败藏起来),必须用 python 手写 xattr:
python3 -c "import os;os.setxattr('/mnt/g/root/.ssh/authorized_keys','security.selinux',b'system_u:object_r:ssh_home_t:s0\0')"
#     常用类型:sshd_key_t / ssh_home_t / hostname_etc_t / machineid_t / etc_t / net_conf_t

# (3) 扩分区:先改分区表再挂载
#     sgdisk -e            # 把 GPT 备份头移到磁盘末尾
#     parted -s resizepart 4 100%
#     顺序反了会 kernel rescan 把已挂载的 fs 变成 I/O error
#     千万别用 sgdisk -d/-n 重建分区,会换掉分区 unique GUID,BIOS-GRUB 就找不到根分区了

# (4) nbd 的坑:
#     - 之前连过别的镜像要先 disconnect 再 connect,否则 mount 会报 can't read superblock
#     - udisks2 会自动挂载 /run/media/<user>/xxx,占着分区导致 umount 失败 → umount -l
```

### 7 ssh 命令行 StrictHostKeyChecking=no 被拒 / 主机密钥变了

> 受管环境里 `ssh -o StrictHostKeyChecking=no` 会被安全策略直接拦掉。
> 用独立的 known_hosts 文件代替:

```bash
ssh-keyscan -H <ip> >> /root/rocky-ks/known_hosts
ssh -o UserKnownHostsFile=/root/rocky-ks/known_hosts -o StrictHostKeyChecking=yes \
    -i <私钥> root@<ip>

# 机器重建过(主机密钥重生成)会报 REMOTE HOST IDENTIFICATION HAS CHANGED
ssh-keygen -R <ip> -f /root/rocky-ks/known_hosts
```

### 8 bash 脚本里 set -e 踩的坑

```bash
# (1) 赋值语句的命令替换失败会直接终止脚本
#     virsh domifaddr <不存在的域> 返回非 0,set -e 下整个脚本退出
ip=$(virsh domifaddr "$n" 2>/dev/null | awk '...' || true)   # 必须加 || true

# (2) local 的多个赋值是"先全部展开再依次赋值"
local name=$1 f="$REG_DIR/.uuid-$name"   # $name 拿到的是外层空值!必须拆成两句

# (3) 管道里要加 --line-buffered / awk 加 fflush(),否则监控脚本收不到实时输出
grep --line-buffered "ERROR" app.log

# (4) find/grep 遇到二进制文件会只打印 "Binary file matches",计数要用 -a
grep -ac "inst.stage2" install.log
```

### 9 Rocky 10 ISO 的引导文件不在 /boot 下

> 直接内核引导要 `vmlinuz` + `initrd.img`,但 Rocky 10 的 ISO 里这两个在
> **`images/pxeboot/`**,顶层 `/boot` 只有 `grub2/` 目录。按 `/boot` 去 cp 会报
> `No such file or directory`。

```bash
mount -o loop,ro Rocky-10.2-x86_64-minimal.iso /mnt/iso
ls /mnt/iso/boot            # 只有 grub2/
ls /mnt/iso/images/pxeboot  # vmlinuz + initrd.img 在这
blkid Rocky-10.2-x86_64-minimal.iso   # LABEL="Rocky-10-2-x86_64-dvd"
```
