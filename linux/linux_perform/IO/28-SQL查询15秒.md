# 28 | 一个 SQL 查询要 15 秒？

原文：[time.geekbang.org/column/article/78633](https://time.geekbang.org/column/article/78633)

商品搜索接口 15 秒才回。iowait 高时连执行别的命令都卡：命令自己也要读目录、加载二进制和库。

## 定位到哪张表

```text
top / iostat     → 盘饱和
pidstat -d       → mysqld
strace -fp PID   → 跟线程；lsof 要用进程 PID 不是 TID
lsof -p mysqld   → /var/lib/mysql/test/products.MYD
```

MyISAM 文件：`.MYD` 数据、`.MYI` 索引、`.frm` 表结构。路径 = 库名/表名。

MySQL 里：

```sql
SHOW FULL PROCESSLIST;
EXPLAIN SELECT * FROM products WHERE productName='geektime';
-- type=ALL, key=NULL, rows=10000  → 全表扫，没用索引
```

生产建议一直开慢查询日志。

## 修法一：加索引

`TEXT`/`BLOB` 建索引必须给前缀长度。选择性（不重复值 / 总行数）越高越好，案例直接用 64：

```sql
CREATE INDEX products_index ON products (productName(64));
```

15 秒 → 3 毫秒。

## 修法二：别把系统缓存冲掉

同机还有个 DataService，循环 `echo 1 > /proc/sys/vm/drop_caches`。MyISAM **不缓存表数据**，全靠 OS 页缓存。缓存被清，每次查询都打盘。停掉干扰应用，即使没索引也会快一截；索引 + 缓存叠起来更好。

`echo 1` 只丢 page cache；不干净再试 `echo 3`。业务代码里频繁 drop_caches 基本是错的（压测机另说，且应和业务隔离）。

不要把性能完全押在系统缓存上——下一讲用 Redis 自己管缓存。
