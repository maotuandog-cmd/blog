# Nginx 知识点总览

对照 [geektime-nginx](https://gitee.com/geektime-geekbang/geektime-nginx) 六册课件 + `examples/`。细节指令当时查 `nginx.org`。

## 1. 它是什么、用在哪

三个主场景：**静态 Web**、**反向代理 / 负载均衡**、**API 网关**（限流、鉴权、改写）。生态向 WAF、CDN、四层转发延伸。发行版：开源 Nginx、**Nginx Plus**、**Tengine**、**OpenResty**（Nginx + LuaJIT）。

为什么快：非阻塞 + `epoll`、worker 少进程多连接、配置热加载、模块稳定。

## 2. 编译与运行

仓库 README 里课程用到的典型 `./configure`（记模块名，不必背路径）：

- HTTP：`ssl` / `v2` / `realip` / `auth_request` / `stub_status` / `gzip_static` / `gunzip` / `sub` / `addition` / `secure_link` / `geoip` / `slice` / `random_index`
- Stream：`stream` + `stream_ssl` / `ssl_preread` / `realip`
- 第三方：`ngx_cache_purge`、`nginx-http-concat`
- 性能：`--with-threads`、`--with-google_perftools_module`、tcmalloc（`--with-ld-opt=-ltcmalloc`）、`--with-debug`

语法：指令有上下文（`main` / `http` / `server` / `location` / `upstream` / `stream`）。冲突时 **更内层覆盖外层**（第三册专门讲「以谁为准」）。`include` 拆文件。`nginx -t` 再 reload。

命令行：

| 信号 / 动作 | 作用 |
|-------------|------|
| `-s reload` / `HUP` | 重载配置：新 worker 起来，旧的处理完再退 |
| `-s quit` / `QUIT` | 优雅退出 |
| `-s stop` / `TERM` | 立刻停 |
| `USR1` | 重新打开日志（配合 logrotate） |
| `USR2` + `WINCH` | 热升级二进制：新 master 起来，再优雅关旧 worker |
| 回滚 | 旧 `nginx.oldbin` 再 `HUP` |

## 3. 进程与事件（第二册核心）

```text
master：读配置、绑端口、管 worker、平滑升级
worker：真正收连接、跑模块；通常 1 核 1 个
```

`worker_processes auto;` + `worker_connections`。理论并发约 `worker_processes × worker_connections`（还受 fd、内存限制）。

事件：Linux 用 **epoll**，只处理就绪连接。请求在 worker 里 **协作式切换**（某个阶段等 I/O 就交出），所以模块里不能阻塞。

内存：请求级 **pool**，结束一起释放，减少碎片。常用容器是 **红黑树**（例如定时器、`limit_req` 的 key）。

## 4. HTTP 请求怎么走（第三册）

11 个阶段（记顺序，配置才知道「这段指令何时生效」）：

| 阶段 | 典型模块 / 指令 |
|------|-----------------|
| POST_READ | realip |
| SERVER_REWRITE | server 级 rewrite |
| FIND_CONFIG | 选 location |
| REWRITE | location 级 rewrite |
| POST_REWRITE | rewrite 后再找一次 location |
| PREACCESS | `limit_req` / `limit_conn` |
| ACCESS | `allow/deny`、`auth_basic`、`auth_request` |
| POST_ACCESS | satisfy |
| PRECONTENT | try_files |
| CONTENT | `proxy_pass` / `fastcgi` / 静态 / `return` |
| LOG | access_log |

**location 匹配**（`examples/locations.conf`）：

1. `=` 精确，命中即停
2. 最长前缀；若是 `^~`，不再走正则
3. 正则 `~` / `~*` **按配置顺序第一条**
4. 否则用刚才的最长前缀；`location /` 兜底

`root` vs `alias`：`root` 会拼上 location 路径，`alias` 替换掉 location 前缀（`static.conf`）。正则里 `alias` 要自己带捕获组文件名。

**rewrite 标志**（`rewrite.conf`）：

| 标志 | 行为 |
|------|------|
| `last` | 改 URI，重新找 location |
| `break` | 改 URI，留在当前 location 继续 |
| `redirect` / `permanent` | 302 / 301 |
| 目标带 `http://` | 对外跳转 |

`try_files` 按序试文件，最后可以 `@named` 或 `=404`。

**变量**：`$uri` 不含参数，`$request_uri` 含；`$host` vs `$http_host`；`$request_id` 贯穿日志。`set` 赋值。`map` / `geo` / `split_clients` 做分流和 AB（`map.conf`）。

日志：自定义 `log_format`；`buffer=` / `flush=` 减 I/O；不需要就 `access_log off`。

## 5. 反向代理与负载均衡（第四册）

`proxy_pass` 到 `upstream`。必带真实 IP 和 Host：

```nginx
proxy_set_header Host $host;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_http_version 1.1;
proxy_set_header Connection "";   # 上游 keepalive 必须清空 Connection
```

`upstream` 常用：

| 指令 | 含义 |
|------|------|
| `weight` | 加权轮询 |
| `max_fails` / `fail_timeout` | 摘除不健康节点 |
| `max_conns` | 单节点并发上限 |
| `keepalive N` | 与上游长连接池 |
| `ip_hash` / `hash $arg_…` | 会话保持 |
| `proxy_next_upstream error timeout http_500` | 失败换下一台 |
| `proxy_intercept_errors` | 把上游 4xx/5xx 交给本机 `error_page` |

多级代理用 `realip`：`set_real_ip_from` 信任的前置 IP，`real_ip_header X-Forwarded-For`，`real_ip_recursive on`。否则 `$remote_addr` 永远是上一跳。

WebSocket：`Upgrade` + `Connection "upgrade"` + HTTP/1.1。  
gRPC：`listen … http2;` + `grpc_pass`。  
四层：`stream { }`，可 `proxy_protocol`、`ssl_preread` 按 SNI 分流。

## 6. 缓存与静态（第四、五册）

```nginx
proxy_cache_path /data/cache levels=1:2 keys_zone=two:10m
                 max_size=1g inactive=10m use_temp_path=off;
proxy_cache two;
proxy_cache_valid 200 1m;
proxy_cache_key $scheme$uri;
add_header X-Cache-Status $upstream_cache_status;
```

防击穿：`proxy_cache_lock on`。过期仍可先返回：`proxy_cache_use_stale updating` + `proxy_cache_background_update on`。清缓存用 `ngx_cache_purge`（仓库 `cache.conf` 的 `/purge`）。

**slice**：大文件按 `slice 1m` 切段缓存，key 带 `$slice_range`，回源带 `Range`，要缓存 206。

静态：`expires`、`open_file_cache`（缓存 open 的 fd/stat，减元数据系统调用）。`gzip` / `gzip_static`。concat 模块把多个静态文件拼成一次响应（第三方）。

浏览器缓存和 Nginx 缓存是两层：`expires` 管客户端，`proxy_cache` 管回源。

## 7. HTTPS / HTTP/2

概念：对称加密传数据、非对称做密钥交换和证书；证书链建立公信。握手贵，所以：

```nginx
ssl_session_cache shared:SSL:10m;
ssl_session_timeout 1d;
ssl_protocols TLSv1.2 TLSv1.3;
ssl_stapling on;
listen 443 ssl http2;
```

客户端证书：`ssl_verify_client optional` + `ssl_client_certificate`（`cache.conf` 里列出了 `$ssl_client_*` 变量）。

HTTP/2：多路复用、HPACK、Server Push（`http2_push` / `Link` + `http2_push_preload`）。Push 要克制，推错比不推更慢。

## 8. 限流、访问控制、防盗链

| 手段 | 要点 |
|------|------|
| `limit_conn` | 并发连接，zone 常用 `$binary_remote_addr` |
| `limit_req` | 漏桶速率 `rate=`，`burst` + `nodelay` |
| `limit_rate` | 单响应限速（字节/秒） |
| `auth_basic` | htpasswd |
| `auth_request` | 把鉴权交给内部 location（可 proxy 到鉴权服务） |
| `satisfy any` | allow 和 auth 满足一个即可 |
| `valid_referers` | 防盗链，看 `$invalid_referer` |
| `secure_link` | URL 带 md5+过期；空=403，0=过期 410 |
| `internal` | 只允许内部跳转，配合 secure_link rewrite |

限流在 **PREACCESS**，比 CONTENT 的 `proxy_pass` 早，能挡住打满上游。

## 9. 性能清单（第五册 + 和 Linux 性能篇对上）

应用内：

- `keepalive` 两端都开：对客户端 `keepalive_timeout`；对上游 `upstream keepalive` + HTTP/1.1 空 Connection
- 少正则、能 `^~` 就不要 `~`
- 日志缓冲或关掉 access
- 缓存命中、`open_file_cache`、sendfile / `tcp_nopush` / `tcp_nodelay`
- `worker_processes` 对齐核数；连接数对齐 `ulimit -n` 和 `worker_rlimit_nofile`

内核（和《Linux 性能优化实战》同一套）：`somaxconn`、`tcp_tw_reuse`、文件句柄、conntrack。瓶颈先看 `stub_status`（活跃连接、等待、读写）再上 `perf`。

`return` 在 server 里会短路整个 server（`return.conf` 里 server 级 `return 405` 会盖掉 location）。

## 10. 扩展：过滤模块、Lua、自己写模块

过滤模块改响应体：`sub_filter`（替换字符串）、`addition`（头尾追加）。在 CONTENT 之后、发给客户端之前。

OpenResty：`access_by_lua_block` / `content_by_lua_block` + `lua_shared_dict` 做动态限流、鉴权。适合「配置写不清、又不想上完整应用」的 API 逻辑；热路径仍尽量用 C 模块。

模块分类：handler（占 CONTENT）、filter、load-balancer、upstream。第三册「模块究竟是什么」：挂到某个阶段的回调，而不是「一个 .so 等于一个功能」。

---

复习口诀：先定 location → 看落在哪一阶段 → 再调 proxy/cache/limit。出事看 error_log（可 `debug`）和 `$upstream_*` 变量（连接时间、状态、cache status）。
