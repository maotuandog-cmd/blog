# 18 | 内存泄漏了怎么定位？

原文：[time.geekbang.org/column/article/75670](https://time.geekbang.org/column/article/75670)

泄漏的内存：应用自己碰不到，系统也不能再分给别人。一直积会触发回收、Swap，最后 OOM。OOM 前往往已经一串性能问题。

## 哪段会漏

| 段 | 谁管 | 会漏吗 |
|----|------|--------|
| 栈 | 系统，出作用域自动回收 | 否 |
| 只读段 / 数据段 | 大小编译期定死 | 否 |
| **堆** | 自己 `malloc` / `free` | 会 |
| **文件映射 / 共享内存** | 自己 `mmap` / `unmap` | 会 |

## 先看趋势，再抓栈

`top` 适合看当下占用；泄漏更要看 **free 是否持续掉、buff/cache 却不怎么动** → `vmstat 3`。占用升高也可能是程序正常长数组，不能单凭这一点定罪。

定位用 bcc 的 `memleak`（内核 ≥ 4.1）：跟踪分配/释放，定期汇总**没释放的字节和调用栈**。

```bash
/usr/share/bcc/tools/memleak -a -p $(pidof app)
# 不知道是哪个进程：去掉 -p
```

老内核没 bcc 用 **Valgrind**。Java 看的是 JVM 栈，用 **jmap** 更合适。内核模块泄漏：`memleak` 也能跟 `kmalloc` / `kfree`；需要 `CONFIG_UPROBE_EVENTS`。

容器里常见：宿主机跑 memleak 找不到容器内二进制路径 → 符号是 `[unknown]`。把二进制拷到同样路径，或按 CPU 篇 perf 那套 `--symfs` / 进容器看。

## 案例：斐波那契

`fibonacci()` 里 `calloc(1024)` 算下一项，调用方从不 `free`。memleak 栈顶就是这个函数。补 `free(v)` 后未释放归零。

更好的修法：这里其实只要一个 `long long`，不必上堆，用栈上变量即可，从根上不分配。

实际项目更难：

- `malloc`/`free` 不在一对，每个成功/异常路径都要放
- 线程 A 分配、线程 B 释放
- 第三方库隐式分配，要你显式释放

习惯：先写释放再写业务。
