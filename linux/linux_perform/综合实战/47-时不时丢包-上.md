# 47 | 案例篇：服务器总是时不时丢包，我该怎么办？（上）

原文：[time.geekbang.org/column/article/85201](https://time.geekbang.org/column/article/85201)

丢包 = 包没到应用就被扔掉。TCP 丢包 ≈ 拥塞 + 重传 → 延迟↑ 吞吐↓。测连通用 `hping3 -S -p 80`，别用 ping（ICMP）。容器要连着看 ns / cgroups / iptables / NAT / 叠加盘。

全程都可能丢：线路 → ring 溢出 → 帧校验/QoS → 路由/超 MTU → 端口没听/超内核限 → socket 缓冲（TCP 溢出会堵 Recv-Q，**UDP 直接丢**）→ 应用异常 → **iptables**。两端都要怀疑。

## 案例

容器 Nginx，`hping3` 10 个 SYN 丢一半，RTT 3ms～3s。进容器从下往上查。

### 链路层

```bash
netstat -i          # RX-ERR / RX-DRP / RX-OVR
tc -s qdisc show dev eth0
```

veth 没有 `ethtool -S` 统计。案例里网卡计数全 0，但 `tc` 看到 `qdisc netem ... loss 30%`，发出 8 个丢 4 个。删掉 netem 后仍 50% 丢——还有下一层。

### 网络层 / 传输层

`netstat -s` 盯错误、丢包、重传（累加值，清只能重启）：

- 11 failed connection attempts
- 4 segments retransmitted
- 11 embryonic SYN_RECV resets
- TCPSynRetrans: 4，TCPTimeouts: 7

主因是**三次握手失败**。下一讲继续往 iptables / conntrack / 抓包挖。
