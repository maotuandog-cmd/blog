# 06 · 调度与资源

> 承接 [[05-存储入门]]。官方：[Resource Management](https://kubernetes.io/docs/concepts/configuration/manage-resources-containers/) · [Taints and Tolerations](https://kubernetes.io/docs/concepts/scheduling-eviction/taint-and-toleration/) · [Assigning Pods to Nodes](https://kubernetes.io/docs/concepts/scheduling-eviction/assign-pod-node/)

## 1. requests / limits

```yaml
resources:
  requests:
    cpu: "100m"
    memory: "128Mi"
  limits:
    cpu: "500m"
    memory: "256Mi"
```

- **requests**：调度与挤兑参考（「需要多少才能进节点」）  
- **limits**：上限；内存超限常被 OOMKill  
- 不设 requests 的「随意调度」在生产容易踩坑  

QoS 粗分：Guaranteed / Burstable / BestEffort（由 requests=limits 等关系决定）。

## 2. 污点与容忍

控制面默认污点：业务 Pod 不调度上去。

```bash
kubectl describe node <名> | rg -i taint
# 实验：去掉控制面污点见 02
# 打污点：
kubectl taint nodes node1 dedicated=gpu:NoSchedule
# 去掉：
kubectl taint nodes node1 dedicated=gpu:NoSchedule-
```

Pod `tolerations` 与污点键值/效果匹配才能上污点节点。

## 3. 节点选择

```yaml
nodeSelector:
  disk: ssd
# 或更强：
affinity:
  nodeAffinity:
    requiredDuringSchedulingIgnoredDuringExecution:
      nodeSelectorTerms:
      - matchExpressions:
        - key: disk
          operator: In
          values: ["ssd"]
```

```bash
kubectl label nodes node1 disk=ssd
```

同节点反亲和可降低单点故障（`podAntiAffinity`），入门知道存在即可。

## 4. Pending 与调度

```bash
kubectl describe pod <名>   # Events: Insufficient cpu / Didn't match ... / node affinity
kubectl get nodes -o custom-columns=NAME:.metadata.name,CPU:.status.allocatable.cpu,MEM:.status.allocatable.memory
```
