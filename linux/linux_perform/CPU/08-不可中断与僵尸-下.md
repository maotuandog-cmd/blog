## iowait 怎么拆

**wa 高 ≠ 磁盘一定是瓶颈。** 只有 I/O 型进程在跑时 wa 也会高，盘可能还很闲。必须看吞吐/IOPS。

```bash
dstat 1 10           # wai 升高时 read 是否跟着涨
pidstat -d 1 20      # 哪个进程在读；D 状态那个可能已经变成 Z，要对全体采样
iostat -dx 1
```

案例：`wai` 高时 `read` 约 34MB/s，是 `app` 在读。对单个 D 进程 `pidstat -d -p` 经常是 0（已经退出成僵尸）。

`strace -p` 可能 `Operation not permitted`：进程已是 **Z**，没法跟。改用：

```bash
perf record -g
perf report          # sys_read → new_sync_read → blkdev_direct_IO
```

源码用了 **`O_DIRECT`**，绕过页缓存，每个请求打到盘上。去掉该选项后 wa 立刻下来。

看内核栈（D 还活着时）：

```bash
cat /proc/<pid>/stack
```

## 僵尸怎么拆

```bash
pstree -aps <zombie_pid>     # 找到父进程
```

案例父进程 `fork` 后把 `wait()` 写在 **for 死循环外面**，永远执行不到。挪进循环（或注册 SIGCHLD）即可。

- 僵尸已经死了，**kill 无效**  
- 父进程若已是 init/systemd，要查谁不断制造僵尸  

## 小结套路

```text
wa 高 → dstat/iostat 确认磁盘忙不忙
     → pidstat -d 找进程
     → D 状态看 /proc/pid/stack 或 perf
     → 是否 O_DIRECT / NFS / 坏盘

Z 多  → pstree 找父进程
     → 查 wait/waitpid/SIGCHLD
```
