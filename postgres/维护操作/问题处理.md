### 2 pg 配置tls 连接, tomcat 应用连接配置

> 以下操作必须有安装openssl

##### 1 pg 端生成server端证书:

```shell

#1 创建自签名证书（server-ca.crt）和自签名证书私钥（server-ca.key）
openssl req -new -x509 -days 365 -nodes -out server-ca.crt -keyout server-ca.key -subj "/CN=root-server-ca"
#2 生成服务器证书请求文件（server.csr）和服务器证书私钥（server.key）。自定义证书支持对一个连接地址或多个连接地址进行保护
openssl req -new -nodes -text -out server.csr -keyout server.key -subj "/CN=xx.xx.xx.xx"
#3 生成服务器证书（server.crt）。
openssl x509 -req -in server.csr -text -days 365 -CA server-ca.crt -CAkey server-ca.key -CAcreateserial  -out server.crt




```

##### 2 修改pg 配置

```
# postgres.conf
ssl = on
ssl_cert_file = 'server.crt'      # 这是证书
ssl_key_file  = 'server.key'      # 这是私钥
ssl_ca_file   = 'server-ca.crt'   # 这是 CA 根证书

# pg_hba.conf
# 不验证客户端ca证书有效性 ,链路加密功能
hostssl all all 0.0.0.0/0 md5
# 验证客户端ca证书有效性
hostssl all all 0.0.0.0/0 md5 clientcert=verify-ca



```

##### 4 生成客户端证书

```


#1生成自签名证书（client-ca.crt）和自签名证书私钥（client-ca.key）
openssl req -new -x509 -days 3650 -nodes -out client-ca.crt -keyout client-ca.key -subj "/CN=root-client-ca"
#生成客户端证书请求文件（client.csr）和客户端证书私钥（client.key）。
openssl req -new -nodes -text -out client.csr -keyout client.key -subj "/CN=<客户端用户名>"
# 生成客户端证书（client.crt）
openssl x509 -req -in client.csr -text -days 365  -CA client-ca.crt -CAkey client-ca.key -CAcreateserial  -out client.crt
#将客户端私钥（client.key）转换为pk8格式。
openssl pkcs8 -topk8 -inform PEM -in client.key -outform der -out client.pk8 -v1 PBE-MD5-DES
# 需要输入密码，连接时需要使用
#需要将上一步生成的server-ca.crt 拷贝到 客户端tomcat 对应的目录下
```

### 3 在pg 中创建没有依赖关系的视图

```
# 表A 表结构
create table a (id int,name varchar(20));
# 创建函数
CREATE OR REPLACE FUNCTION get_a_data()
RETURNS TABLE(id int, name varchar(20))
LANGUAGE plpgsql AS $$
BEGIN
    RETURN QUERY EXECUTE 'SELECT id, name FROM a';
EXCEPTION WHEN undefined_table THEN
    RETURN;
END;
$$;
# 创建视图
CREATE OR REPLACE VIEW b AS SELECT * FROM get_a_data();
```

### 4 触发器方式限制插入条目数量

```sql
-- 1. 创建示例表
CREATE TABLE your_table (
    id SERIAL PRIMARY KEY,
    condition_col VARCHAR(50),  -- 条件列
    data TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 2. 创建触发器函数
CREATE OR REPLACE FUNCTION check_record_limit()
RETURNS TRIGGER AS $$
DECLARE
    record_count INTEGER;
BEGIN
    -- 统计相同条件的记录数
    SELECT COUNT(*) INTO record_count
    FROM your_table
    WHERE condition_col = NEW.condition_col;
  
    -- 检查是否超过48条
    IF record_count >= 48 THEN
        RAISE EXCEPTION '每个条件最多只能有48条记录，当前条件已有 % 条', record_count;
    END IF;
  
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 3. 创建BEFORE INSERT触发器
CREATE TRIGGER enforce_record_limit
BEFORE INSERT ON your_table
FOR EACH ROW
EXECUTE FUNCTION check_record_limit();
```

### 7 [polar\_resource\_manager](https://github.com/ApsaraDB/PolarDB-for-PostgreSQL/blob/38948055/external/polar_resource_manager/polar_resource_manager.c#L108-L109) 不支持cgroup2的情况下报错Failed to get the instance memory usage keep

> [polar\_resource\_manager](https://github.com/ApsaraDB/PolarDB-for-PostgreSQL/blob/38948055/external/polar_resource_manager/polar_resource_manager.c#L108-L109) 插件作用
>
> 核心就是 在内核 OOM killer 动手之前，先由插件自己腾内存，避免整实例被 OS 杀掉。
>
> 它是 PolarDB 的后台 worker，按 `stat_interval`（默认 500ms）读本实例 cgroup 内存：用量（rss + mapped\_file，可选加上 pfsdaemon）和上限。用量超过 `total_mem_limit_rate`（默认上限的 95%）时，按策略主动处理会话：
>
> * 优先杀空闲连接（`SIGTERM`）
> * 仍超则杀活跃会话，或只取消 SQL（`SIGINT`）
> * 也可随机杀一批，策略由 `mem_release_policy` 控制
>
> 目的写在代码里：防止 OOM 导致 所有连接断开。内核 OOM 常直接干掉 `postgres` 主进程，实例整体挂掉；插件是用户态抢先释放，尽量保住 postmaster。
>
> 它 不能禁止 OS kill。内存还是涨、cgroup 读失败（例如纯 v2 路径不对）、或释放不够快时，内核照样会 OOM。它只是尽量把“整实例被杀”变成“先丢掉部分会话”。

处理方式：  

postgresql.conf 添加参数，并重启服务

```
polar_resource_manager.enable_resource_manager=off
```
