# 17 | 如何利用系统缓存优化程序？

原文：[time.geekbang.org/column/article/75242](https://time.geekbang.org/column/article/75242)

Buffer / Cache 是 OS 管的，程序不能直接控制内容和生命周期。评估效果看 **缓存命中率** = 从缓存拿到的请求 / 全部请求。

## 工具

bcc（要内核 ≥ 4.1，工具在 `/usr/share/bcc/tools`，默认不在 PATH）：

| 工具 | 看什么 |
|------|--------|
| `cachestat` | 整机：TOTAL / MISSES / HITS / DIRTIES / Buffers / Cached |
| `cachetop` | 每进程 HITS、MISSES、脏页、读/写命中率 |

`pcstat`（Go）：某个文件有多少页在缓存、占比。

`dd` 的 `iflag=direct` / `oflag=direct` 可绕过 cache 测盘。

**Direct I/O ≠ 裸 I/O**：`O_DIRECT` 跳过 Buffer/Cache；裸 I/O 跳过文件系统，**还有 Buffer**。`cachetop` **不算 Direct I/O**，所以绕过缓存时会看到「命中率 100% 但量对不上」。

## 案例一：同一文件读两次

清缓存后第一次 `dd` 读 512MB：约几十 MB/s，命中率约 50%（不是 0 —— **预读**把后面的页提前读进 Cache）。第二次变成数 GB/s，命中 100%，`pcstat` 显示文件全在缓存。

结论：系统缓存对重复读极有效。用 `dd` 测文件系统性能时必须清缓存或 Direct I/O，否则测的是内存。

## 案例二：读得慢但 cachetop 显示 100%

每秒读 32MB，却要 0.9s。cachetop 显示 HITS=1024、读命中 100%。按页 4KB 换算：5 秒里只有 4MB 命中 ≈ 0.8MB/s，跟 32MB/s 对不上。

`strace` 看到：`openat(..., O_RDONLY|O_DIRECT)` —— 绕过了系统缓存。去掉 `O_DIRECT` 后 0.03s 读完 32MB，HITS 变成 40960，正好 32MB/s。

算命中量：`HITS × 4KB / 间隔秒数`，要跟应用实际 I/O 对一下，别被「100%」骗了。

## 应用层还要自己的缓存

OS 页缓存不够控热点和过期。程序里可用堆/栈自己缓存，或 Redis 这类外部缓存。

同一问题可以从 CPU（大量 D、iowait）或缓存（Direct I/O、命中量对不上）两条线走进去，最后会汇到同一个系统调用。
