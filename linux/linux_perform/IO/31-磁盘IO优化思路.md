# 31 | 磁盘 I/O 性能优化的几个思路

原文：[time.geekbang.org/column/article/79368](https://time.geekbang.org/column/article/79368)

目标：更快做完 I/O，或者干脆少做、不做。先基准，再改最值钱的那一处。优化 I/O 可能抬高 CPU/内存，要一起看。多数情况从**应用层**减写入、错峰就够。

## 先用 fio 摸天花板

别在系统盘或有数据的盘上写测。`filename` 指块设备会毁掉上面的文件系统。

```bash
fio -name=randread -direct=1 -iodepth=64 -rw=randread \
    -ioengine=libaio -bs=4k -size=1G -numjobs=1 -runtime=1000 \
    -group_reporting -filename=/dev/sdb
```

| 参数 | 含义 |
|------|------|
| `direct=1` | 跳过页缓存 |
| `iodepth` | 异步同时发出的请求上限 |
| `rw` | read/write 顺序，randread/randwrite 随机 |
| `ioengine` | sync / libaio / mmap / net |
| `bs` | 块大小，默认 4K |

报告看 **IOPS、bw、lat**：

- `slat`：提交到开始执行
- `clat`：提交到完成（同步 I/O 时 clat=0，提交和完成是同一动作）
- `lat`：fio 创建 I/O 到完成；异步约等于 slat+clat

更贴应用：`blktrace` 录访问 → `blkparse` 出 bin → `fio --read_iolog=` 重放。

## 应用

1. 追加写代替随机写
2. 走缓存 I/O（页缓存）
3. 进程内缓存或 Redis，别把命押在会被别人 `drop_caches` 的系统缓存上；`fopen/fread` 还有 libc 缓冲，`open/read` 没有
4. 反复读写同一块：`mmap` 少拷贝
5. 必须同步写：合并后 `fsync`，不要每条 `O_SYNC`
6. 共享盘：cgroup 限制 IOPS/吞吐
7. CFQ 下 `ionice`：Idle / Best-effort / Realtime，后两个还有 0–7（越小越优先）

## 文件系统

- 选型：xfs 更大分区/更多文件，不能缩小；ext4 能缩小。Ubuntu 默认 ext4，CentOS 7 默认 xfs
- `tune2fs` 调特性；挂载 `noatime`、日志模式 journal/ordered/writeback
- 脏页：`dirty_expire_centisecs`、`dirty_writeback_centisecs`、`dirty_ratio`；dentry/inode 回收倾向 `vfs_cache_pressure`（越大越爱收）
- 不需持久化：`tmpfs`（`/dev/shm` 默认约一半内存）

## 磁盘

- SSD 换 HDD；RAID；调度：SSD/虚拟机常用 **noop**，库多用 **deadline**（写 `/sys/block/<dev>/queue/scheduler`）
- 日志和库分盘
- 顺序读多：加大预读 `read_ahead_kb`（默认 128KB）；`blockdev --setra` 单位是 512B，数值是 kb 的两倍
- 加长 `nr_requests` 可提吞吐、延迟也会升
- 性能陡降先查硬件：`dmesg`、`smartctl`、`badblocks`、`e2fsck`（虚拟机/RAID 上 smartctl 常失效）
