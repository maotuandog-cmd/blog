# 03 | CPU 上下文切换是什么？（上）

原文：[time.geekbang.org/column/article/69859](https://time.geekbang.org/column/article/69859)

## 一句话

Linux 用时间片轮转制造「同时跑很多任务」的错觉。每次换任务都要把 **CPU 寄存器 + 程序计数器（PC）** 存起来再装下一份，这就是 **CPU 上下文切换**。次数过多时，CPU 大量时间花在保存/恢复上，真正干活的时间变少，**负载也会升**。

## CPU 上下文是什么

运行任何任务前必须有的环境：

- **CPU 寄存器**：极快的小内存  
- **程序计数器 PC**：当前/下一条指令位置  

切换：保存当前 → 加载下一个 → 跳到新 PC。旧上下文放在内核里，任务再被调度时装回来。

任务不只是进程/线程，**硬件中断处理程序**也是一种任务。因此切换分三类。

## 三类切换

### 1. 进程上下文切换

Linux 把空间分成：

- **内核空间 Ring 0**：可直接访问全部资源  
- **用户空间 Ring 3**：必须 **系统调用** 才能碰特权资源  

进程在用户空间叫用户态，陷入内核叫内核态。系统调用（`open/read/write/close`）会发生 **两次 CPU 上下文切换**（进内核再出来），但 **同一个进程**，不换虚拟内存。这通常叫 **特权模式切换**，不等于进程切换。

**进程切换**只能发生在内核态，要多保存/恢复：

- 用户空间：虚拟内存、栈、全局变量  
- 内核空间：内核栈、寄存器  

还有 **TLB 刷新**：虚拟地址映射变了，内存访问变慢；多核上共享缓存被刷还会连累别的核。  
一次切换大约几十纳秒到数微秒，频繁时非常可观。

**何时会调度（换进程）**

1. 时间片用完（公平调度；CFS 里更准确叫虚拟运行时间）  
2. 资源不够（如内存）被挂起  
3. 自己 `sleep`  
4. 更高优先级进程抢占  
5. 硬件中断打断当前进程  

### 2. 线程上下文切换

- **线程** = 调度单位  
- **进程** = 资源单位  

同进程线程共享虚拟内存/全局变量，切换时这些不用动，只换栈和寄存器 → **比跨进程便宜**。  
跨进程的线程切换 ≈ 进程切换。

### 3. 中断上下文切换

中断为了快，会打断正常调度。不保存用户态虚拟内存等，只保存内核态中断所需状态（寄存器、内核栈、硬件参数）。

同一 CPU 上，中断优先级高于进程，不会和进程切换「同时发生」。中断处理必须短；次数太多同样吃 CPU。

## 开销大致排序

进程切换 > 同进程线程切换 > 中断切换 > 内核态/用户态模式切换  

（协程、用户态函数调用要看实现，不能一概而论。）

## 小结

- 切换是多任务的必要成本，平时不必紧张  
- **过多**才会变成性能问题：CPU 空转在保存/恢复
