# 51 | 案例篇：动态追踪怎么用？（下）

原文：[time.geekbang.org/column/article/86710](https://time.geekbang.org/column/article/86710)

ftrace/perf 不够灵活；eBPF 才是 Linux 版 DTrace。多数问题：**perf + 火焰图**；要按事件做统计（I/O 大小分布等）再用 eBPF/SystemTap。容器里最大坑是 **debug 符号不在同一 ns**。

## perf 动态探针

```bash
perf probe --add do_sys_open
perf probe -V do_sys_open          # 从 debuginfo 看参数
perf probe --del probe:do_sys_open
perf probe --add 'do_sys_open filename:string'
perf record -e probe:do_sys_open -aR ls
perf script
perf probe --del probe:do_sys_open

# 用户态库函数（要二进制带 -g）
perf probe -x /bin/bash 'readline%return +0($retval):string'
```

**别用 strace 压库**：ptrace 来回切内核，还 SIGSTOP 挂进程。换 `perf trace`（基于内核事件，还能全系统跟）。过滤用 `perf trace -e fs:do_sys_open`。

## eBPF / BCC

三步：生成 BPF 字节码 → 载入内核 → 回用户态。BCC 用 Python 包一层，事件处理仍要写 C。现成工具在 `/usr/share/bcc/tools/`。新特性绑死新内核。

## 其他

- **SystemTap**：eBPF 之前最接近 DTrace；RHEL 上稳，别的发行版易炸；能撑 3.x 旧内核
- **sysdig**：≈ strace + tcpdump + htop + iftop + lsof + docker inspect；≥4.14 可走 eBPF

| 场景 | 优先 |
|------|------|
| 找热点 | perf + 火焰图 |
| 已知函数、看调用图 | ftrace / trace-cmd |
| 自定义统计、新内核 | eBPF/BCC |
| 旧内核 / RHEL | SystemTap |
| 容器现场 | sysdig |
