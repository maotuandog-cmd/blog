正常情况下，执行 `sshd -V` 的标准输出应该类似于：

`OpenSSH_9.3p1, OpenSSL 3.5.7 9 Jun 2026`

  

而在你提供的输出中，原本应该是 `OpenSSH_版本号` 的位置变成了 `host`。这并非系统错误，而是系统管理员在**编译 OpenSSH 源码时，故意修改了源代码以隐藏真实的 sshd 版本号**。

  

这种做法在服务器安全加固中被称为“通过隐蔽提升安全性（Security by Obscurity）”。以下是具体的原因和实现方式：

  

### 1. 是如何做到隐藏/修改版本号的？

既然管理员是通过源码编译来指定 OpenSSL 版本的（如上一个回答所述），那么在编译之前，他们只需修改 OpenSSH 源码包中的一个头文件即可。

  

在 OpenSSH 的源码目录中，有一个名为 `version.h` 的文件，里面定义了版本信息：

  

C

```
/* 默认的 version.h 长这样 */
#define SSH_VERSION     "OpenSSH_9.3"
#define SSH_PORTABLE    "p1"
```

管理员只需要用文本编辑器将这里的值改掉：

  

C

```
/* 修改后的 version.h */
#define SSH_VERSION     "host"
#define SSH_PORTABLE    ""
```

保存后继续执行 `make` 和 `make install`。编译完成后，新生成的 `sshd` 二进制文件就会把自己的名字报告为 `host`，从而实现了你看到的输出：`host, OpenSSL 3.5.7 9 Jun 2026`。

  

### 2. 为什么要费劲去隐藏 sshd 版本号？

主要目的是**欺骗漏洞扫描器和恶意攻击者**：

  

- **规避自动化攻击：** 互联网上有大量的自动化爬虫和黑客工具（如 Shodan、Nmap 等）。当它们扫描服务器的 22 端口时，会自动抓取 SSH 的 Banner（欢迎信息）。如果直接暴露了类似 `OpenSSH_7.4` 这样带有已知高危漏洞的老版本，攻击者就会直接使用针对性的自动化脚本进行攻击。
    
      
    
- **应付安全审计扫描：** 很多企业的安全扫描软件（如 Nessus、绿盟等）是通过“版本比对”来报高危漏洞的。有时候企业虽然打了安全补丁（比如红帽官方提供的 backport 补丁），但大版本号没变，扫描器依然会误报。为了清零扫描报告上的“中高危漏洞”，一些运维人员会选择直接抹除或伪造版本号。
    
      
    

### 总结

你看到的输出说明，这台服务器的管理员不仅**手动编译升级了 OpenSSL 加密库**，而且在编译 OpenSSH 的过程中**顺手修改了源码**，把版本号硬编码成了 `host`，从而达到隐藏真实服务版本、防范漏洞探测的目的。
