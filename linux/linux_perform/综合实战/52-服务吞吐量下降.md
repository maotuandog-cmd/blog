# 52 | 案例篇：服务吞吐量下降很厉害，怎么分析？

原文：[time.geekbang.org/column/article/87342](https://time.geekbang.org/column/article/87342)

套路：指标 → 跟原理对照找异常 → perf/火焰图/bcc 找热点。host 网络方便直接看套接字。`wrk -c` 是并发，输出 Requests/sec 是 QPS，别混。

案例 Nginx + php-fpm（Hello World），wrk 1000 并发只有 189 QPS，全是非 2xx/3xx。带宽没打满，从 **TCP 连接数**下手。

## 1. conntrack 打满

`ss -s`：estab 只有 5，timewait 1100+。`dmesg`：`nf_conntrack: table full`。max=200 且用尽。调到 1048576 后 QPS ~5382，但仍大量异常。

## 2. php-fpm 子进程不够

Nginx 日志 **499**（扩展码：服务端还没回，客户端 2s 超时先关）。php-fpm：`reached max_children setting (5)`。每进程约 20MB，按内存/CPU 估，案例改成 20。成功请求从 8k 涨到 15k。

## 3. 监听队列溢

`netstat -s | grep socket`：`listen queue overflowed` / `SYNs to LISTEN sockets dropped` 在涨。`ss -ltnp` LISTEN 的 Recv-Q 顶到 Send-Q。

作者原文把 LISTEN 的 Recv-Q/Send-Q 当全连接队列来调（不严谨）。正确顺序：**先看/调 `tcp_max_syn_backlog`（半连接），再调全连接**。全连接受 `somaxconn` 和 `listen(backlog)` 限制。

案例把 Nginx `backlog`、php-fpm `listen.backlog` 提到 8192，`net.core.somaxconn` 提到 65536，套接字不再丢。

## 4. 临时端口耗尽

Nginx 连 php-fpm 时自己是**客户端**，要占本地端口。日志 `Cannot assign requested address`（EADDRNOTAVAIL）。`ip_local_port_range=20000 20050` 只有 50 个。加大范围。`tcp_tw_reuse=1` 也是给**客户端**复用 TIME_WAIT 端口，服务端 TIME_WAIT 不会因此变少。

火焰图热点常见 `inet_sendmsg` / `tcp_write_xmit`，对照原理再决定要不要 tw_reuse。

层层抠完：QPS ~5000，几乎没有非 2xx。压测时同时看 `sar` 吞吐和丢包，避免客户端网络先成瓶颈。CPU 只用一半却 502/499，多半是应用过载（连接失败尝试暴涨）。
