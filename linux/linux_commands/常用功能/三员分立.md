这是一份基于标准 Linux 系统的“三员分立”（系统管理员、安全保密管理员、安全审计员）建设与权限配置标准操作文档。

  

本方案主要通过**账号分离、`sudo` 权限控制（黑白名单）以及文件访问控制**来实现。这不仅是服务器安全加固的最佳实践，也是满足“等保2.0”合规要求的核心步骤。

  

> **⚠️ 高危操作预警：**
> 
> 在进行以下配置时，**请务必保持当前的 root SSH 终端不要关闭**。另外开一个终端进行测试。如果配置错误导致普通用户无法提权，你可以通过保留的 root 终端进行回退。
> 
>   

## 一、 角色规划与职责定义

在配置之前，我们先明确三员的职责边界：

  

|**角色名称**|**系统账号**|**核心职责**|**权限红线 (禁止项)**|
|---|---|---|---|
|**系统管理员**|`sysadm`|负责系统日常运维、网络配置、业务服务启停、文件管理。|禁止修改密码策略、禁止查看/修改审计日志。|
|**安全管理员**|`secadm`|负责安全策略、防火墙、密码分配、账号权限管理。|禁止干预业务运行、禁止查看/修改审计日志。|
|**审计管理员**|`audadm`|负责审查其他两员的操作记录、配置和导出审计日志。|禁止修改系统配置、禁止修改安全策略。|

## 二、 创建三员账号

首先，使用 `root` 账号登录系统，创建这三个独立的用户并设置强密码。

  

Bash

```
# 1. 创建系统管理员
useradd sysadm
passwd sysadm  # 输入并确认强密码

# 2. 创建安全管理员
useradd secadm
passwd secadm  # 输入并确认强密码

# 3. 创建审计管理员
useradd audadm
passwd audadm  # 输入并确认强密码
```

## 三、 配置 Sudo 权限分离 (核心步骤)

我们将使用 `visudo` 命令来编辑 `/etc/sudoers` 文件。为了清晰和易于维护，我们通过定义 **命令别名 (Cmnd_Alias)** 来分配权限。

  

运行以下命令打开配置编辑器：

  

Bash

```
visudo
```

在文件末尾，添加以下配置代码块：

  

Plaintext

```
# ==========================================
# 1. 定义命令别名 (分类管理)
# ==========================================

# 审计类命令：查看系统日志、操作 auditd
Cmnd_Alias AUDIT_CMDS = /usr/sbin/ausearch, /usr/sbin/aureport, /usr/sbin/auditctl, /usr/bin/tail -f /var/log/*, /bin/cat /var/log/*, /bin/less /var/log/*, /bin/more /var/log/*

# 安全类命令：修改密码、管理用户属性、防火墙、SELinux
Cmnd_Alias SEC_CMDS = /usr/bin/passwd, /usr/bin/chage, /usr/sbin/usermod, /usr/sbin/visudo, /usr/bin/firewall-cmd, /usr/sbin/ufw, /usr/sbin/semanage, /usr/sbin/setenforce

# ==========================================
# 2. 分配角色权限 (三员相互制约)
# ==========================================

# 系统管理员 (sysadm)：拥有绝大部分权限，但【剔除】安全命令和审计命令
sysadm  ALL=(ALL)  ALL, !SEC_CMDS, !AUDIT_CMDS

# 安全管理员 (secadm)：【仅能】执行安全相关的命令
secadm  ALL=(root) SEC_CMDS

# 审计管理员 (audadm)：【仅能】执行审计和日志查看命令
audadm  ALL=(root) AUDIT_CMDS
```

_保存并退出编辑器（如果系统默认编辑器是 vi，按 `Esc`，输入 `:wq` 回车）。_

  

## 四、 强化系统日志与审计目录权限

默认情况下，普通用户可能无法读取 `/var/log` 下的文件。我们需要将日志和审计目录的权限分配给审计员。

  

我们使用 `setfacl` (访问控制列表) 让 `audadm` 用户对日志目录拥有只读权限，而不影响系统原有权限。

  

Bash

```
# 确保安装了 acl 工具
yum install acl -y      # CentOS/RedHat
# apt-get install acl -y # Ubuntu/Debian

# 赋予 audadm 对 /var/log 和 /var/log/audit 的访问权
setfacl -m u:audadm:r-x /var/log
setfacl -m u:audadm:r-x /var/log/audit
setfacl -R -m u:audadm:r /var/log/audit/
```

## 五、 测试与验证（验收标准）

新开三个 SSH 终端，分别用 `sysadm`、`secadm`、`audadm` 登录，进行如下越权测试，验证配置是否生效：

  

### 1. 测试 sysadm (系统管理员)

- ✅ `sudo systemctl restart sshd` (正常执行，允许运维服务)
    
      
    
- ❌ `sudo passwd root` (被拒绝，无权管理密码)
    
      
    
- ❌ `sudo cat /var/log/secure` (被拒绝，无权看安全日志)
    
      
    

### 2. 测试 secadm (安全管理员)

- ✅ `sudo passwd sysadm` (正常执行，允许分配密码)
    
      
    
- ✅ `sudo firewall-cmd --state` (正常执行，允许管理防火墙)
    
      
    
- ❌ `sudo systemctl restart nginx` (被拒绝，无权干涉业务)
    
      
    

### 3. 测试 audadm (审计管理员)

- ✅ `sudo ausearch -m USER_LOGIN` (正常执行，允许审查登录事件)
    
      
    
- ✅ `sudo cat /var/log/messages` (正常执行，允许查看日志)
    
      
    
- ❌ `sudo useradd testuser` (被拒绝，无权修改系统)
    
      
    

## 六、 终极加固：收回 root 权限

当三员测试全部通过，系统不再依赖 `root` 账号进行日常操作时，为了满足合规要求，应限制 `root` 账号的直接登录。

  

Bash

```
# 编辑 SSH 配置文件
vi /etc/ssh/sshd_config
```

找到 `PermitRootLogin`，修改为：

  

Plaintext

```
PermitRootLogin no
```

保存后，使用 `sysadm` 账号重启 SSH 服务：

  

Bash

```
sudo systemctl restart sshd
```

至此，Linux 服务器的标准“三员分立”体系建设完成。



为了满足更高安全级别（如等保 2.0 三级及以上）的要求，或者在金融、政务等高度敏感的环境中，仅做基础的 `sudo` 限制是不够的。我们还需要解决“命令逃逸”（Shell Escape）**、**底层审计（auditd）规则**以及**强制密码策略等问题。

  

以下是深度加固版的“三员分立”操作文档，细化到了底层配置和防漏洞机制。

  

> **⚠️ 核心警告：** 以下涉及底层的认证和提权配置，**请务必保留一个具有 root 权限的 SSH 连接不要关闭**，以便在配置失误导致所有用户无法 `sudo` 时能够随时回滚。
> 
>   

## 阶段一：强制密码策略与账号安全建设（Secadm 专属）

三员账号不仅要创建，还必须受到严格的密码复杂度规则限制。

  

### 1. 强化系统密码复杂度机制

编辑 `/etc/security/pwquality.conf`（基于 CentOS/RHEL/Kylin），强制要求强密码：

  

Ini, TOML

```
# 密码最小长度 12 位
minlen = 12
# 至少包含大写、小写、数字、特殊符号中的 3 种
minclass = 3
# 新密码不能与旧密码相同字符数大于 4
difok = 4
```

### 2. 创建账号并强制定期改密

通过 `chage` 命令强制要求三员账号定期更换密码。

  

Bash

```
# 创建账号
useradd sysadm && passwd sysadm
useradd secadm && passwd secadm
useradd audadm && passwd audadm

# 限制密码有效期最长 90 天，过期前 7 天警告
chage -M 90 -W 7 sysadm
chage -M 90 -W 7 secadm
chage -M 90 -W 7 audadm
```

## 阶段二：防逃逸级别的 Sudo 权限分离

在基础配置中，我们给了审计员 `less` 和 `more` 命令去查看日志。但高级攻击者可以通过在 `less` 界面中输入 `!sh` 直接获取 root Shell（这叫“命令逃逸”）。我们必须使用 `NOEXEC` 标签来封死这个漏洞。

  

使用 `visudo` 修改 `/etc/sudoers`，替换为以下更严谨的配置：

  

Plaintext

```
# ==========================================
# 1. 定义命令别名
# ==========================================

# 【系统管理员命令】所有非安全、非审计命令。
# 明确禁止 su、sudoedit、chmod 等可能越权的命令。
Cmnd_Alias SYS_CMDS = ALL
Cmnd_Alias SYS_BANNED = /bin/su, /usr/bin/sudoedit, /usr/bin/chmod, /usr/bin/chown, /usr/bin/passwd, /usr/sbin/visudo, /usr/sbin/ausearch, /usr/sbin/aureport, /usr/sbin/auditctl

# 【安全管理员命令】密码、用户、防火墙、权限修改
Cmnd_Alias SEC_CMDS = /usr/bin/passwd, /usr/sbin/usermod, /usr/bin/chage, /usr/sbin/visudo, /usr/bin/chmod, /usr/bin/chown, /usr/bin/chattr, /usr/bin/firewall-cmd

# 【审计管理员命令】审计工具
Cmnd_Alias AUDIT_TOOLS = /usr/sbin/ausearch, /usr/sbin/aureport, /usr/sbin/auditctl, /usr/bin/tail, /bin/cat
# 存在 Shell 逃逸风险的阅读器
Cmnd_Alias AUDIT_READERS = /usr/bin/less, /usr/bin/more, /usr/bin/vim

# ==========================================
# 2. 权限精确绑定
# ==========================================

# sysadm：允许所有，但扣除安全、审计及越权命令
sysadm  ALL=(ALL)  ALL, !SYS_BANNED

# secadm：仅允许安全控制相关命令
secadm  ALL=(root) SEC_CMDS

# audadm：允许审计命令。对阅读器强制增加 NOEXEC 限制（禁止在阅读器内执行子命令）
audadm  ALL=(root) AUDIT_TOOLS, NOEXEC: AUDIT_READERS
```

## 阶段三：底层审计系统 (auditd) 规则配置 (Audadm 专属)

系统自带的 `/var/log/secure` 只能记录成功或失败的登录，无法记录“谁修改了核心文件”。我们需要为审计员（audadm）配置 `auditd` 守护进程。

  

以 root 身份编辑审计规则文件 `/etc/audit/rules.d/audit.rules`，在末尾添加：

  

Bash

```
# 1. 监控账户和密码文件的篡改 (w=写, a=属性修改)
-w /etc/passwd -p wa -k identity_changes
-w /etc/shadow -p wa -k identity_changes
-w /etc/group -p wa -k identity_changes

# 2. 监控提权配置文件的篡改
-w /etc/sudoers -p wa -k sudoers_changes
-w /etc/sudoers.d/ -p wa -k sudoers_changes

# 3. 监控安全相关的二进制文件是否被异常调用
-w /usr/bin/passwd -p x -k passwd_execution
-w /usr/sbin/usermod -p x -k user_modification

# 4. 锁定规则（此行必须在最后，重启生效，防止规则被恶意清空）
-e 2
```

重启审计服务：

  

Bash

```
systemctl restart auditd
```

> **审计员工作流演示：**
> 
> 以后 `audadm` 登录后，无需一行行翻日志，只需运行 `sudo ausearch -k sudoers_changes` 即可瞬间查出是谁在什么时间试图修改过 sudo 权限。
> 
>   

## 阶段四：不可篡改标记与日志保护

即使 `root` 权限被拆分，恶意黑客利用漏洞拿到系统级 root 依然可能删除日志。安全管理员（secadm）需要利用底层文件系统属性（`chattr`）锁定日志。

  

Bash

```
# 赋予 audadm 读取审计日志的系统级权限 (ACL)
setfacl -m u:audadm:r-x /var/log/audit
setfacl -m u:audadm:r /var/log/audit/audit.log

# 重点：安全管理员使用 chattr 让审计日志"只能追加，不能删除和修改"
chattr +a /var/log/audit/audit.log
chattr +a /var/log/secure
chattr +a /var/log/messages
```

_(注意：配置 `chattr +a` 后，连 root 也不能用 `rm` 删除这些日志，必须由 secadm 解除锁定才能清理空间。)_

  

## 阶段五：收缩入口，只允许三员 SSH 登录

为了切断普通业务账号和 root 账号被直接爆破的风险，需要在 SSH 层面做白名单。

  

编辑 `/etc/ssh/sshd_config`：

  

Plaintext

```
# 1. 绝对禁止 root 远程登录
PermitRootLogin no

# 2. SSH 登录白名单：仅允许这三个管理员账号从 SSH 登录，业务账号（如 nginx, mysql, dev）必须通过其他方式（如跳板机/堡垒机）或由系统管理员切换进入
AllowUsers sysadm secadm audadm
```

重启 SSH 服务：

  

Bash

```
systemctl restart sshd
```

## 三员日常协同工作场景模拟（重要）

通过以上配置，系统不再有一个可以“为所欲为”的用户。当公司来了一位新员工需要一个服务器账号时，流程如下：

  

1. **`sysadm` 创建用户环境：**
    
    `sysadm` 执行 `sudo useradd newdev -m` 创建账号及目录。但他**无法**使用 `passwd` 为其设置密码，输入密码命令会被系统拒绝。
    
      
    
2. **`secadm` 赋予密码并分配权限：**
    
    `secadm` 介入，执行 `sudo passwd newdev` 赋予初始密码，并强制要求新员工首次登录改密（`sudo chage -d 0 newdev`）。
    
      
    
3. **`audadm` 监督审计：**
    
    `audadm` 每天登录，执行 `sudo aureport --auth` 审查登录情况，检查 `sysadm` 和 `secadm` 是否有违规越权行为。
