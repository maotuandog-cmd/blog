# 55 | 套路篇：分析性能问题的一般步骤

原文：[time.geekbang.org/column/article/88667](https://time.geekbang.org/column/article/88667)

告警来了：从**系统资源**和**应用程序**两边收口。资源用 USE；应用本质只有三类——资源、依赖服务、自身。

## 系统资源

硬件：CPU / 内存 / 盘 / 网。软件：fd、conntrack、socket 缓冲。指标多来自 `/proc`、`/sys`，应先进监控，出事先查图再登录。

| 资源 | 确认瓶颈 | 往下钻 |
|------|----------|--------|
| CPU | `top` / `vmstat` / `pidstat` | 监控找出高 CPU 进程 → `strace` 系统调用、`perf` 热点、动态追踪 |
| 内存 | `free` / `vmstat` | 监控找占用最大的进程和历史（是否泄漏）→ 再看进程地址空间/分配 |
| I/O | `iostat`：使用率、延迟、等待队列 | `pidstat`/`vmstat` 找来源 → `strace`/`lsof`/`perf` |
| 网络 | 按协议栈分层：链路吞吐丢包错误软中断；网络层路由分片叠加；传输层连接/吞吐/延迟/重传；应用层 QPS、socket 缓冲 | 监控找哪一层丢 → `netstat`/`tcpdump`/`bcc` |

## 应用程序

1. **资源瓶颈**：就是上一节那些，同一套招
2. **依赖服务**：DB / 缓存 / 中间件——全链路跟踪
3. **自身**：多线程、死锁、算法复杂度——看内部 metrics 和日志；还不够就 `strace`、火焰图、动态追踪

系统和应用互相拖：泄漏占内存、狂 I/O 拖整机。很多时候两边是同一个根因，不必重复分析。
