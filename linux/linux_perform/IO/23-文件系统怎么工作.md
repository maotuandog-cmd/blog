# 23 | Linux 文件系统是怎么工作的？

原文：[time.geekbang.org/column/article/76876](https://time.geekbang.org/column/article/76876)

磁盘提供持久化；文件系统在上面给出树状文件。Linux **一切皆文件**（普通文件、目录、块设备、套接字、管道）都走 VFS。块设备「裸 I/O」跳过的是具体磁盘文件系统，不是 VFS。

## inode 和 dentry

| | inode | dentry（目录项） |
|--|-------|------------------|
| 记什么 | 元数据：编号、大小、权限、mtime、数据位置 | 文件名、inode 指针、与其他 dentry 的关系 |
| 存哪 | **磁盘**（也占空间），会再缓存进内存 | **只在内存**，是缓存；掉电可从盘上重建 |
| 关系 | 一个文件一个 inode | 多对一（硬链接 = 多个名字，同一个 inode） |

文件名持久化在**目录这个特殊文件**里，不是只活在 dentry 缓存。开机不会把整棵树建进内存，**按需**建一小部分。

读写最小单位不是 512B 扇区，文件系统用 **逻辑块**（常见 4KB = 8 个扇区）。

格式化后磁盘三块：超级块（整体状态）、inode 区、数据块区。

## VFS

用户只跟 VFS 标准接口说话。底下三类：

- 磁盘：Ext4、XFS、OverlayFS
- 内存：`/proc`、`/sys`（不占盘，占内存）
- 网络：NFS、SMB、iSCSI

必须挂到某个挂载点才能用。系统先挂根 `/`，再挂其他。

VFS 的 `inode_cache` 和具体 FS 的 `ext4_inode_cache` 是两层：抽象层一份，实现层一份。

## 四种 I/O 分类（别混）

| 维度 | 一对 |
|------|------|
| 标准库缓存 | 缓冲 I/O（stdio 内部缓冲） vs 非缓冲 I/O（直接系统调用） |
| 页缓存 | **直接 I/O**（`O_DIRECT`，跳过 Page Cache） vs 非直接 I/O（默认） |
| 线程等不等 | 阻塞 vs 非阻塞（`O_NONBLOCK`） |
| 完成通知 | 同步（`O_SYNC` / `O_DSYNC` 等数据落盘才返回） vs 异步（`O_ASYNC` + SIGIO） |

直接 I/O 仍跟文件系统交互。再跳过文件系统才是**裸 I/O**。详情见第 32 讲。

## 怎么看

容量：`df -h` 看空间；**`df -i` 看 inode**。空间还很多但写不进去，多半是小文件把 inode 用光。

`df` 比 `du` 大很多：文件已删但 fd 还握着。`lsof | grep deleted`；找不到再查失效描述符。

缓存：

```bash
cat /proc/meminfo | grep -E 'SReclaimable|Cached'
cat /proc/slabinfo | grep -E '^#|dentry|inode'
slabtop    # c 按大小，a 按活跃对象
```

`find / -name ...` 会把路过的 **dentry + inode**（含各 FS 的 inode cache）抬起来，页缓存也会跟着涨一点。
