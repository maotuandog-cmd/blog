# 10 · 升级与备份入门

> 承接 [[09-排障手册]]。etcd 机制与五轴：[[quant67/01-etcd生产内核]] · apiserver 运维篇见 quant67 原文 14。  
> 官方：  
> [Upgrading kubeadm clusters](https://kubernetes.io/docs/tasks/administer-cluster/kubeadm/kubeadm-upgrade/) ·  
> [Backing up an etcd cluster](https://kubernetes.io/docs/tasks/administer-cluster/configure-upgrade-etcd/#backing-up-an-etcd-cluster)

只覆盖 **单控制面 kubeadm** 的节奏与原则；多控制面/外置 etcd 读官方全文。

## 1. 升级原则

1. **先读**目标 minor 的 Changelog 与 kubeadm 升级页  
2. 遵守版本偏斜：一次升 **一个 minor**（如 1.32 → 1.33）  
3. 顺序：**备份 → 升控制面 kubeadm → apply 升级 → 升控制面 kubelet → 逐个 worker**  
4. CNI / CSI / Ingress 查兼容表，必要时先升插件  

## 2. 升级前备份

### 2.1 清单与配置

```bash
# 有 git 的清单仓库：打 tag
cp -a $HOME/.kube/config ~/kubeconfig.bak.$(date +%F)
sudo tar -C /etc -czf ~/k8s-etc-kubernetes-$(date +%F).tgz kubernetes
```

### 2.2 etcd 快照（stacked etcd 常见）

控制面节点，按官方用 etcdctl 对本地 etcd 打 snapshot（端点、证书路径以你集群为准，多在 `/etc/kubernetes/pki/etcd/`）：

```bash
# 示意：具体命令以官方「Backing up an etcd cluster」为准
sudo ETCDCTL_API=3 etcdctl snapshot save /root/etcd-snapshot-$(date +%F).db \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key
sudo etcdctl snapshot status /root/etcd-snapshot-*.db -w table
```

快照文件离机保存。恢复是高危操作，演练再在生产做。

## 3. 控制面升级（示意流程）

以升到 **v1.33.x** 为例（版本号换成实际 patch）：

```bash
# 1) 换 apt 源到目标 minor（同 02 的 pkgs.k8s.io 写法），只先升 kubeadm
sudo apt-mark unhold kubeadm
sudo apt-get update && sudo apt-get install -y kubeadm=1.33.x-*
sudo apt-mark hold kubeadm
kubeadm version

# 2) 规划与执行
sudo kubeadm upgrade plan
sudo kubeadm upgrade apply v1.33.x

# 3) 升 kubelet / kubectl
sudo apt-mark unhold kubelet kubectl
sudo apt-get install -y kubelet=1.33.x-* kubectl=1.33.x-*
sudo apt-mark hold kubelet kubectl
sudo systemctl daemon-reload
sudo systemctl restart kubelet
kubectl get nodes   # 控制面版本应更新
```

drain 对**唯一控制面**要谨慎；维护窗口操作。官方页对「是否 drain 控制面」有说明，按当前文档执行。

## 4. Worker 升级

逐台：

```bash
kubectl drain <node> --ignore-daemonsets --delete-emptydir-data
# 节点上：升级 kubeadm → kubeadm upgrade node → 升级 kubelet/kubectl → restart kubelet
kubectl uncordon <node>
```

## 5. 证书

kubeadm 证书默认有期限；过期会导致 apiserver 起不来。

```bash
kubeadm certs check-expiration
# 续期见官方：kubeadm certs renew
```

## 6. 检查清单

- [ ] 升级前有 etcd 快照 + 清单/配置备份  
- [ ] 只跨一个 minor，kubeadm 与 kubelet 顺序正确  
- [ ] 升级后 nodes Ready、核心系统 Pod Running、业务冒烟通过  
- [ ] 知道 `certs check-expiration`
