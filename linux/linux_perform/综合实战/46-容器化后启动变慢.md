# 46 | 案例篇：为什么应用容器化后，启动慢了很多？

原文：[time.geekbang.org/column/article/84953](https://time.geekbang.org/column/article/84953)

综合实战开篇。容器化后排错要把 **cgroups、命名空间、iptables/NAT、叠加盘、CNI/CSI 插件** 一起算进去。Java 应用最容易踩「容器限了，进程看不见」。

## 现象

```bash
docker run --name tomcat --cpus 0.1 -m 512M -p 8080:8080 -itd feisky/tomcat:8
```

curl 先 reset，偶发一次 `Hello, world!`，然后容器没了。

```bash
docker inspect tomcat -f '{{json .State}}' | jq
# OOMKilled: true, ExitCode: 137
dmesg | grep -A20 oom
# memory: usage 524288kB, limit 524288kB
```

JSP 只申请 256MB，容器给了 512MB，仍被 cgroup OOM。

## 根因 1：JVM 按宿主机内存估堆

容器里 `free -m` 仍是主机 8GB。JVM 默认最大堆 ≈ 物理内存 1/4 → 约 2GB，远超 `-m 512M`。`/proc` 当年不知道 cgroup 限额。

```bash
docker exec tomcat java -XX:+PrintFlagsFinal -version | grep HeapSize
# MaxHeapSize ≈ 2GB
docker run ... -e JAVA_OPTS='-Xmx512m -Xms512m' ...
```

注意堆=512M 和容器=512M 仍可能 OOM（非堆、metaspace、native）。堆要留余量。Java 10+ 能感知容器限额。

## 根因 2：CPU 限额让启动干等

限制内存后启动仍要 **22s**。`top` 看系统很闲，java 只有 10%。`pidstat -t` 启动瞬间 **%wait 高达 97%**——线程在等调度，不是算得慢。`--cpus 0.1` = 10% CPU。改成 `--cpus 1`，启动 **2s**。

不要图省事去掉限额：一个容器打满会拖死整机。限额要按压测估，而不是不设。
