# 50 | 案例篇：动态追踪怎么用？（上）

原文：[time.geekbang.org/column/article/86490](https://time.geekbang.org/column/article/86490)

服务不停、不改代码，靠探针看内核/应用在干什么。相对 ptrace 开销通常 <5%。难复现的线上问题最适合。鼻祖是 Solaris DTrace；Linux 上是 ftrace / perf / eBPF / SystemTap。

找大方向用 **perf + 火焰图（采样）**；已知函数名再 **ftrace 逐次跟踪（全量、准）**。Java 的 btrace 只覆盖 JVM。

## 事件源

| 类 | 是什么 | 例子 |
|----|--------|------|
| 硬件 | PMC | cache、周期、分支预测 |
| 静态探针 | 源码里预先埋好 | 内核 **tracepoints**；用户态 **USDT**（MySQL 等内置） |
| 动态探针 | 运行时往函数入口/返回插 | 内核 **kprobe/kretprobe**（要 `CONFIG_KPROBE_EVENTS`）；用户态 **uprobe/uretprobe** |

## 机制

- **ftrace**：debugfs（`/sys/kernel/debug/tracing`），函数/事件跟踪
- **perf**：静态事件 + `perf probe` 自定义
- **eBPF**：内核里常驻运行时，C 写 BPF，Linux 版 DTrace
- 核外：SystemTap（脚本先编成模块，依赖调试符号，启动慢）、BCC、sysdig

## ftrace 五步（或 `trace-cmd`）

```bash
cd /sys/kernel/debug/tracing   # 没有就 mount -t debugfs nodev /sys/kernel/debug
cat available_tracers          # function / function_graph 最常用
echo do_sys_open > set_graph_function
echo function_graph > current_tracer
echo funcgraph-proc > trace_options
echo 1 > tracing_on
ls
echo 0 > tracing_on
cat trace                      # CPU、任务、耗时、调用关系

trace-cmd record -p function_graph -g do_sys_open -O funcgraph-proc ls
trace-cmd report
```

CentOS 写 `current_tracer`（不是 current_trace）。function_graph 在小内存机上可能把系统卡死。
