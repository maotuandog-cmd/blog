在 Nginx 中，处理 `OPTIONS` 方法漏洞最有效的方式是==在配置文件中直接拒绝该请求（如果你的业务不需要跨域预检），或者移除敏感的响应标头==。

请根据你的业务需求选择以下方案之一，修改后记得执行 `nginx -s reload` 生效。





方案一：直接禁用 OPTIONS 方法（推荐，最彻底）

如果你的网站不需要处理跨域（CORS）预检请求，可以直接返回 405 Method Not Allowed。

在 `nginx.conf` 的 `server` 或 `location` 块中加入以下配置：

```nginx
server {
    listen 80;
    server_name yourdomain.com;

    # 仅允许 GET 和 POST 方法，其他方法（包括 OPTIONS）一律拒绝
    if ($request_method !~ ^(GET|POST)$ ) {
        return 405;
    }
    
    # 或者单独禁用 OPTIONS
    # if ($request_method = OPTIONS) {
    #     return 405;
    # }
}

 方案二：允许 OPTIONS 但隐藏服务器版本信息

如果你的前端业务需要跨域请求，Nginx 会自动发送 `OPTIONS` 预检响应。此时不能禁用它，但必须隐藏 Nginx 版本号，防止攻击者进行针对性漏洞利用。

在 `nginx.conf` 的 `http` 块中确保开启以下参数：

```nginx
http {
    # 隐藏 Nginx 的具体版本号（例如不再显示 Nginx/1.18.0，只显示 nginx）
    server_tokens off;
}


方案三：清理自定义敏感标头

有时后端服务器（如 Tomcat、Node.js）在响应 `OPTIONS` 时会附带敏感标头。你可以利用 Nginx 作为反向代理，强制清除这些隐患标头：

```nginx
location / {
    proxy_pass http://backend_server;

    # 隐藏后端返回的 Server 和 X-Powered-By 标头
    proxy_hide_header X-Powered-By;
    proxy_hide_header Server;
}
```
