# 15 | Linux 内存是怎么工作的？

原文：[time.geekbang.org/column/article/74272](https://time.geekbang.org/column/article/74272)

进程看到的是**虚拟地址空间**，只有内核能直接碰物理内存（DRAM）。虚拟地址通过页表映射到物理页；没用到的虚拟内存不会占物理内存。

## 地址空间

| | 32 位 | 64 位 |
|--|--------|--------|
| 用户空间 | 低 3G | 低 128T |
| 内核空间 | 高 1G | 高 128T |
| 中间 | — | 未定义 |

用户态只能碰用户空间。每个进程的内核空间映射的是**同一块**物理内存，进内核态后就能访问内核。

## 映射：页表 / MMU / TLB / 缺页

- 页通常 **4 KB**。MMU 按页映射，不是按字节。
- 页表记录虚拟页 → 物理页。查不到就 **缺页异常**：进内核分配物理页、改页表，再回用户态。
- **TLB** 是 MMU 里页表的高速缓存。进程切换会刷 TLB，所以少切进程能让内存访问更快。
- 页太小导致页表项爆炸。Linux 用 **四级页表**（只用到的区块才建表）和 **大页**（2MB / 1GB，Oracle、DPDK 常用）。

页表本体在内存里；MMU 是查映射的硬件，TLB 是它的缓存。

## 用户空间从低到高

1. 只读段：代码、常量
2. 数据段：全局变量
3. **堆**：动态分配，低地址向上长（`malloc` → 小块走 `brk`）
4. **文件映射段**：动态库、共享内存，高地址向下长（`mmap`）
5. **栈**：局部变量、调用上下文，大小基本固定，常见 8MB

64 位布局类似，只是空间大得多。

## 分配：brk vs mmap

C 库 `malloc`：

| | 小块（&lt;128K）`brk` | 大块 `mmap` |
|--|------------------------|-------------|
| 做法 | 推堆顶 | 在文件映射段找空闲区 |
| 释放 | **不立刻还给系统**，缓存再用 | 立刻还给系统 |
| 代价 | 少缺页，但忙时易碎片 | 每次都缺页，内核负担大 |

两种调用当时**都不真正给物理页**，第一次访问才缺页分配。

物理页由 **伙伴系统** 按页分配，相邻空闲页合并减碎片。比一页还小的内核对象用 **slab**（建在伙伴系统上的缓存）。**slab 只服务内核**，用户态 `malloc` 不用 slab。

用完要 `free` / `unmap`。只分配不放 = 泄漏，严重会把机器吃光。

## 内存紧张时系统会干什么

1. **回收缓存**：LRU 丢掉最近最少用的页
2. **Swap**：不常访问的匿名页换到磁盘（换出 / 换入）。磁盘远慢于内存，Swap 一多就是性能问题
3. **OOM**：按 `oom_score` 杀进程。占内存越大分越高，占 CPU 越多分越低

调分：`oom_adj` 范围 `[-17, 15]`，越大越容易被杀，`-17` 禁止 OOM。

```bash
echo -16 > /proc/$(pidof sshd)/oom_adj
dmesg | grep -Ei 'kill|oom|out of memory'
```

## 怎么看

`free`：看系统。**available = 未用 + 可回收缓存**，一般比 free 大；不是所有 cache 都能收。

`top` 按 `M` 按内存排：

| 列 | 含义 |
|----|------|
| VIRT | 申请过的虚拟内存，**没分配物理页也算** |
| RES | 常驻物理内存，不含 Swap 和共享 |
| SHR | 共享相关：真共享 + 代码段 + 非共享动态库也会算进来 |
| %MEM | 物理内存占比 |

注意：VIRT ≫ RES 正常。**不要把各进程 SHR 加起来当总占用**——代码段会重复计。
