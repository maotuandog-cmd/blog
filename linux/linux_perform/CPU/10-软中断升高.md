# 10 | 软中断 CPU 使用率升高怎么办？

原文：[time.geekbang.org/column/article/72147](https://time.geekbang.org/column/article/72147)

接 [[09-软中断]]。生产里软中断瓶颈 **绝大多数是网络收发，尤其是 NET_RX**。

## 现象

`hping3 -S -p 80 -i u100 <ip>` 打 SYN 小包后：

- SSH 终端明显变卡（不是键盘中断，是 SSH 自己也走网卡被挤）  
- `top` 里 **us/sy 都很低**，但 **%si** 有几 percent，`ksoftirqd` 相对最忙  
- **load 甚至是 0**——别被 load 骗了  

卡顿是因为 **网络延迟/丢包**，用第三台机器 `ping` 对比 hping3 开前后即可验证。

## 套路

```bash
top                  # 按 1，看 si
watch -d cat /proc/softirqs    # 看谁涨得最快 → 常是 NET_RX
sar -n DEV 1         # PPS vs BPS
tcpdump -i eth0 -n tcp port 80
```

`sar -n DEV` 关键列：`rxpck/s`（PPS）、`rxkB/s`（BPS）。  
案例：PPS≈12607，BPS≈664KB → 平均帧约 **54 字节 = 小包**。  
`tcpdump` 见大量 `Flags [S]` → **SYN FLOOD**。

应急：在交换机/防火墙封源 IP。原理放到网络篇。

## 小结

```text
si 升高 → /proc/softirqs 看类型
       → NET_RX 则 sar 看 PPS/BPS（是不是小包）
       → tcpdump 看包类型和源
```
