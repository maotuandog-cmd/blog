```

// 2. 将优先级恢复为默认值 1
cfg.members[0].priority = 1; 
// votes = 1 是正常投票节点的默认值，无需修改

```

### 4 MongoDB 备份日志： panic: send on closed channel

原因：
1 oom kill
2 主动kill
解决办法：
1 查看本机资源情况，主要内存。如果内存使用率高，考虑扩容内存或者，降低其他组件使用率。
2 重新执行备份。

### 6 WiredTiger error (0) [1751526412:940052][10:0x7f46b9986a00], file:collection-6-2241825848872286060.wt, txn-recover: read checksum error for 32768B block at offset 660738048: calculated block checksum of 3894076463 doesn't match expected checksum of 4224336044 Raw: [1751526412:940052][10:0x7f46b9986a00], file:collection-6-2241825848872286060.wt, txn-recover: read checksum error for 32768B block at offset 660738048: calculated block checksum of 3894076463 doesn't match expected checksum of 4224336044

原因: **数据块损坏（data corruption）**，通常意味着你有物理磁盘损坏、意外断电、文件系统错误或非正常关机导致 MongoDB 数据文件部分损坏。

修复方式:

```shell
mongod --dbpath /your/dbpath --repair
```

### 9 Failed: error connecting to db server: server returned error on SASL authentication step: Authentication failed.

问题原因:  mongo对用户设置了来源限制

解决方式:

```
# 查找有限制的用户
use admin
db.system.users.find(
  { authenticationRestrictions: { $exists: true } },
  { user:1, db:1, authenticationRestrictions:1 }
).pretty()
# 根据上一步查找 ,去除对应的限制
use admin
db.updateUser("root", {
  roles: [ { role: "root", db: "admin" } ],
  authenticationRestrictions: [ ]   // 显式设置为空数组
})

```

### 11 mongodump 备份导致 session用完处理

处理方式:
1 如果是secondary节点,可以重启节点,然后在备份脚本全量备份 mongodb连接串中添加:

```
replicaSet=rs0&authSource=admin&readPreference=secondaryPreferred
```

### 12 centos 7 启动 mongodb 报错 message":"std::exception::what(): Operation not permitted\\nActual exception type: std::system\_error"

**解决方法：** 尝试放开安全限制重新启动容器。

* **Docker 命令行：** 在启动命令中加入 `--security-opt seccomp=unconfined`。
* **Docker Compose：**
  **YAML**

  ```
  security_opt:
    - seccomp:unconfined
  ```
