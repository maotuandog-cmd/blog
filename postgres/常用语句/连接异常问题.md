PostgreSQL 分析**连接异常问题**，一般从 **连接数、连接失败原因、网络、认证、连接池、数据库资源** 几个方向排查。

---

# 1. 查看当前连接情况

## 当前连接总数

```sql
SELECT count(*)
FROM pg_stat_activity;
```

查看最大连接数：

```sql
SHOW max_connections;
```

例如：

```
当前连接: 198
最大连接: 200
```

说明接近连接耗尽。

---

## 按用户统计连接

```sql
SELECT
    usename,
    count(*)
FROM pg_stat_activity
GROUP BY usename
ORDER BY count(*) DESC;
```

查看哪个用户占用连接。

---

## 按客户端 IP 统计

```sql
SELECT
    client_addr,
    count(*)
FROM pg_stat_activity
GROUP BY client_addr
ORDER BY count(*) DESC;
```

排查：

- 某台应用服务器连接暴增
    
- 异常客户端
    

---

# 2. 查看连接状态

```sql
SELECT
    state,
    count(*)
FROM pg_stat_activity
GROUP BY state;
```

常见状态：

|状态|说明|
|---|---|
|active|正在执行 SQL|
|idle|空闲连接|
|idle in transaction|危险|

---

## 查长时间空闲事务

```sql
SELECT
    pid,
    usename,
    client_addr,
    now()-xact_start AS tx_time,
    query
FROM pg_stat_activity
WHERE state='idle in transaction'
ORDER BY tx_time DESC;
```

例如：

```
idle in transaction
2 hours
```

容易导致：

- 锁不释放
    
- MVCC 膨胀
    
- 查询变慢

# 3. 连接失败日志分析

查看 PostgreSQL 日志。

Ubuntu：

```bash
grep "connection" /var/log/postgresql/*.log
```

常见异常：

---

## 连接数满

日志：

```
FATAL: sorry, too many clients already
```

原因：

```text
max_connections 已达到上限
```

处理：

查看：

```sql
SHOW max_connections;
```

临时释放：

```sql
SELECT pg_terminate_backend(pid)
FROM pg_stat_activity
WHERE state='idle';
```

长期：

增加连接池，例如：

- PgBouncer
    
- HikariCP
    

---

## 密码认证失败

日志：

```
FATAL: password authentication failed for user
```

检查：

```sql
SELECT usename FROM pg_user;
```

检查：

```
pg_hba.conf
```

例如：

```conf
host all all 0.0.0.0/0 scram-sha-256
```

---

## 用户不存在

日志：

```
FATAL: role "xxx" does not exist
```

创建：

```sql
CREATE USER xxx PASSWORD 'password';
```

---

## IP 不允许连接

日志：

```
no pg_hba.conf entry
```

修改：

```bash
vim pg_hba.conf
```

添加：

```conf
host all all 192.168.1.0/24 scram-sha-256
```

reload：

```bash
systemctl reload postgresql
```

# 4. 查看监听情况

服务器：

```bash
ss -lntp | grep 5432
```

正常：

```
LISTEN 0 244 *:5432
```

如果只监听：

```
127.0.0.1:5432
```

远程无法连接。

修改：

```conf
listen_addresses='*'
```

# 6. 查看连接来源和异常客户端

```sql
SELECT
    client_addr,
    application_name,
    state,
    count(*)
FROM pg_stat_activity
GROUP BY
    client_addr,
    application_name,
    state
ORDER BY count(*) DESC;
```

常见：

```
client_addr     count
10.10.1.20      500
```

说明应用连接泄漏。

# 7. 检查连接池问题

应用常见问题：

## 未释放连接

表现：

```
connections 持续增长
```

解决：

- 设置连接池最大连接数
    
- 设置 idle timeout
    

例如：

HikariCP：

```properties
maximumPoolSize=50
idleTimeout=60000
connectionTimeout=3000
```

---

## 大量短连接

表现：

```
LOG: connection received
LOG: disconnection
```

频繁出现。

解决：

增加：

- PgBouncer
    
- 连接复用

## 一条快速诊断 SQL

执行：

```sql
SELECT
    now(),
    count(*) total,
    count(*) FILTER(where state='active') active,
    count(*) FILTER(where state='idle') idle,
    count(*) FILTER(where state='idle in transaction') idle_tx
FROM pg_stat_activity;
```

可以快速判断：

- 是否连接打满
    
- 是否大量空闲
    
- 是否存在异常事务
    

如果你能提供**具体报错日志**（例如 `FATAL: too many clients already`、`connection reset`、`timeout`、`could not connect`），可以进一步定位。
