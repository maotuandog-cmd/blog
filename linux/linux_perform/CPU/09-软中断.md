# 09 | 怎么理解 Linux 软中断？

原文：[time.geekbang.org/column/article/71868](https://time.geekbang.org/column/article/71868)

## 为什么要拆成上下半部

中断会打断正在跑的进程，处理程序必须尽快结束。处理太长会关中断过久，**后面的中断可能丢失**。

Linux 把中断分成：

| | 上半部（硬中断） | 下半部（软中断） |
|--|------------------|------------------|
| 何时 | 立刻，关中断 | 延迟，开中断 |
| 做什么 | 跟硬件紧耦合、时间敏感 | 剩下的大量工作 |
| 网卡收包 | 把数据拷进内存、清寄存器、发软中断 | 协议栈解析，送到应用 |

「取外卖」：接电话说知道了 = 上半部；下楼取餐谈发票 = 下半部。

软中断不只是设备下半部，内核自己的事件也算，如 **调度 SCHED、RCU、定时器 TIMER**。

每个 CPU 一个内核线程 **`ksoftirqd/N`**。`ps` 里名字带方括号的一般是内核线程。

下半部更细还可以是：软中断、**tasklet**（基于软中断，只在一个 CPU 跑一次）、**工作队列**（可睡眠）。

## 怎么看

```bash
cat /proc/softirqs     # 各类软中断在各核上的累加次数
cat /proc/interrupts   # 硬中断
ps aux | grep '\[ksoftirqd'
top                    # %si 软中断 CPU
mpstat -P ALL 1
```

注意：

1. 类型：`NET_RX` 收包、`NET_TX` 发包最常见  
2. 各 CPU 次数应大致同数量级；**TASKLET 可以很偏科**（绑在发起它的那个核）  
3. 次数是累加值，要 **watch 两次作差** 看速率  

大量**小包** → 硬中断 + 软中断都频繁，这是网络性能问题的常见根。应用侧发太碎的包也会把内核软中断打满。
