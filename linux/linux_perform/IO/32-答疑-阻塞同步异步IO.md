# 32 | 答疑：阻塞/非阻塞 与 同步/异步

原文：[time.geekbang.org/column/article/79734](https://time.geekbang.org/column/article/79734)

I/O 篇答疑。两套分类**对象不同**，不要揉成一句话。

## 1. 四象限

| | 说的是谁 |
|--|----------|
| **阻塞 / 非阻塞** | 调用者（应用线程）等不等 |
| **同步 / 异步** | 执行者（内核）怎么通知结果 |

- 阻塞：没结果就卡住当前线程
- 非阻塞：立刻返回，自己轮询或等事件（套接字加 `O_NONBLOCK`，常配 epoll）
- 同步：内核处理完才通过这次系统调用把结果给你（`read` 没读到盘数据不会返回）
- 异步：内核先回「收到了」，做完再用回调/事件通知（`aio_read`）

套接字 `send()` 没设 `O_NONBLOCK` 会一直堵。不可中断 D 状态等的是**块设备 I/O**，**不包括**等套接字。

## 2. `find /` 会抬哪类缓存

文件名和目录关系在 **dentry**，按需构建，所以 dentry（以及 inode cache）升高。构建元数据要从 FS 读，`vmstat` 里 **buff 和 cache 都会涨**。只读已打开文件的内容，一般不抬 Buffer。

## 3. strace 看不见 write

漏了 **`-f`**，写在子线程里。工具输出不合逻辑，先查默认选项和原理。

## 4. 停掉 DataService，没索引也变快

MyISAM **只缓存索引，不缓存数据**。查询走不了索引就要从 `.MYD` 读进内存。DataService 每 3 秒 `drop_caches`，cache 涨三次就掉回去。停掉之后 cache 涨到稳定，`bi` 和 iowait 归零——数据全在页缓存里了。

所以：不要把性能押在系统缓存上。InnoDB 自己缓存索引+数据；或 Redis / Memcached。

## 额外

- `df` 100%、关进程后掉到 85%：进程还握着已删文件的 fd（日志、解压临时文件）。`lsof | grep deleted`
- 读文件内容不抬 Buffer；`find` 那种扫元数据才会
