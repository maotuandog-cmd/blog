# 43 | 套路篇：网络性能优化的几个思路（上）

原文：[time.geekbang.org/column/article/83783](https://time.geekbang.org/column/article/83783)

先定目标再调：NAT 网关拼 PPS；数据库/缓存拼低延迟；Web 吞吐和延迟都要。按协议栈分层做基准（pktgen → iperf → wrk），底层数字就是上层天花板。尽量用生产流量回放。

## 应用层

I/O：epoll 换 select/poll；AIO 能并发发起但不容易写对。

进程：主进程 + worker；或多进程同端口 + `SO_REUSEPORT`。

协议：长连接、缓存少打网、Protobuf 等压体积、DNS 缓存/预取/HTTPDNS。小 payload 可自己拼包。非阻塞 + epoll 比「必须异步」更通用。

## 套接字

读缓冲满就收不进；写缓冲满 `write` 阻塞。吞吐理想值 ≈ **带宽 × 延迟**（BDP）。

内核选项是**全局**，`setsockopt` 是**单个**，总和仍受全局限制。套接字缓冲和 TCP 缓冲是同一块内存，只是作用域不同。看占用：`/proc/net/sockstat`、`ss`。

| 项 | 作用 |
|----|------|
| `net.core.optmem_max` | 每个套接字辅助缓冲上限 |
| `net.core.rmem_max` / `wmem_max` | 套接字收/发上限 |
| `net.ipv4.tcp_rmem` / `tcp_wmem` | TCP 收/发，三个数 min/default/max，内核自动调 |
| `net.ipv4.tcp_mem` | TCP 全局内存页数（min/pressure/max）；满了新连接进不来，`dmesg` 会 `tcp_mem: out of memory` |
| `udp_mem` | min/pressure/max |

套接字选项：`TCP_NODELAY` 关 Nagle；`TCP_CORK` 攒大包（会堵住小包）；`SO_SNDBUF`/`SO_RCVBUF` 改单个缓冲。
