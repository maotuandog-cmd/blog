PostgreSQL 分析锁问题，主要看 **谁阻塞谁、锁类型、阻塞 SQL、事务状态**。下面是一套生产常用排查流程。

---

## 1. 查看当前锁等待

### 查看正在等待锁的 SQL

```sql
SELECT
    pid,
    usename,
    client_addr,
    application_name,
    wait_event_type,
    wait_event,
    now() - query_start AS waiting_time,
    query
FROM pg_stat_activity
WHERE wait_event_type = 'Lock'
ORDER BY waiting_time DESC;
```

如果有结果，说明正在等锁。

---

## 2. 找出阻塞者和被阻塞者（最重要）

```sql
SELECT
    blocked.pid AS blocked_pid,
    blocked.query AS blocked_query,
    blocked.query_start AS blocked_start,
    blocking.pid AS blocking_pid,
    blocking.query AS blocking_query,
    blocking.query_start AS blocking_start
FROM pg_stat_activity blocked
JOIN pg_locks blocked_locks
ON blocked.pid = blocked_locks.pid
JOIN pg_locks blocking_locks
ON blocking_locks.locktype = blocked_locks.locktype
AND blocking_locks.database IS NOT DISTINCT FROM blocked_locks.database
AND blocking_locks.relation IS NOT DISTINCT FROM blocked_locks.relation
AND blocking_locks.page IS NOT DISTINCT FROM blocked_locks.page
AND blocking_locks.tuple IS NOT DISTINCT FROM blocked_locks.tuple
AND blocking_locks.pid <> blocked.pid
JOIN pg_stat_activity blocking
ON blocking.pid = blocking_locks.pid
WHERE NOT blocked_locks.granted;
```

结果类似：

|blocked_pid|blocking_pid|说明|
|---|---|---|
|12345|6789|12345 被 6789 阻塞|

重点处理 `blocking_pid`。

---

## 3. 查看某个 PID 在干什么

例如阻塞者：

```sql
SELECT *
FROM pg_stat_activity
WHERE pid = 6789;
```

关注：

```
state
query_start
xact_start
query
```

例如：

```
state: idle in transaction
xact_start: 2 hours ago
query: update order set status=1 ...
```

这种通常是问题源头。

---

## 4. 查看所有锁详情

```sql
SELECT
    l.pid,
    a.usename,
    a.state,
    l.locktype,
    l.mode,
    l.granted,
    c.relname,
    a.query
FROM pg_locks l
LEFT JOIN pg_stat_activity a
ON l.pid=a.pid
LEFT JOIN pg_class c
ON l.relation=c.oid
ORDER BY l.pid;
```

重点看：

### 常见锁类型

|锁|说明|
|---|---|
|AccessShareLock|普通 SELECT|
|RowExclusiveLock|INSERT/UPDATE/DELETE|
|ShareLock|索引/约束相关|
|AccessExclusiveLock|ALTER TABLE、TRUNCATE|

---

## 5. 找长事务（最常见原因）

```sql
SELECT
    pid,
    usename,
    state,
    now()-xact_start AS transaction_time,
    query
FROM pg_stat_activity
WHERE xact_start IS NOT NULL
ORDER BY transaction_time DESC;
```

危险：

```
idle in transaction
持续几十分钟/小时
```

原因：

- 开事务后忘记 commit
    
- 程序连接池异常
    
- 手工执行 SQL 忘提交
    

---

## 6. 查看锁住的是哪个表

```sql
SELECT
    a.pid,
    a.query,
    c.relname,
    l.mode
FROM pg_locks l
JOIN pg_stat_activity a
ON l.pid=l.pid
LEFT JOIN pg_class c
ON l.relation=c.oid
WHERE c.relname IS NOT NULL;
```

---

## 7. 终止异常会话

确认 PID 后：

### 优雅停止

```sql
SELECT pg_cancel_backend(6789);
```

取消当前 SQL。

---

### 强制断开

```sql
SELECT pg_terminate_backend(6789);
```

会回滚未提交事务。

---

## 8. 查看死锁

日志开启：

```conf
log_lock_waits = on
deadlock_timeout = 1s
```

查看：

```bash
grep deadlock postgresql.log
```

典型：

事务 A：

```
update A
等待 B
```

事务 B：

```
update B
等待 A
```

形成环。

---

## 9. 常见锁问题场景

### 场景1：UPDATE 阻塞 SELECT

通常：

- 大事务 UPDATE
    
- 未提交
    

处理：

```sql
select * from pg_stat_activity;
```

找长事务。

---

### 场景2：DDL 卡住

例如：

```sql
ALTER TABLE xxx ADD COLUMN
```

会申请：

```
AccessExclusiveLock
```

会阻塞所有访问。

---

### 场景3：批量 DELETE

例如：

```sql
delete from big_table;
```

长时间持锁。

建议：

```sql
delete from big_table
where id < 10000;
```

分批提交。

## 推荐一条生产排查 SQL

直接看阻塞链：

```sql
SELECT
    blocked.pid AS blocked_pid,
    blocked.query AS blocked_sql,
    blocking.pid AS blocking_pid,
    blocking.query AS blocking_sql,
    now()-blocking.query_start AS blocking_time
FROM pg_stat_activity blocked
JOIN pg_locks bl
ON blocked.pid=bl.pid
JOIN pg_locks kl
ON bl.locktype=kl.locktype
AND bl.database IS NOT DISTINCT FROM kl.database
AND bl.relation IS NOT DISTINCT FROM kl.relation
AND bl.pid<>kl.pid
JOIN pg_stat_activity blocking
ON kl.pid=blocking.pid
WHERE NOT bl.granted;
```

---

如果你是在生产环境排查，建议先执行这三个：

```sql
-- 1. 当前等待锁
select * from pg_stat_activity where wait_event_type='Lock';

-- 2. 长事务
select pid,now()-xact_start,query from pg_stat_activity where xact_start is not null;

-- 3. 阻塞链
查看谁 block 谁
```

把结果贴出来，可以进一步判断是**事务未提交、DDL锁、行锁冲突还是死锁**。
