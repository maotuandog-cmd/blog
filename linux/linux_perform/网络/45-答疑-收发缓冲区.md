# 45 | 答疑（五）：网络收发过程中，缓冲区位置在哪里？

原文：[time.geekbang.org/column/article/84529](https://time.geekbang.org/column/article/84529)

网络篇收尾。四大基础模块（CPU / 内存 / I/O / 网络）到这里学完。

## 缓冲区都在内核内存里，不在网卡芯片上

| 缓冲 | 干什么 | 和内存篇 Buffer/Cache |
|------|--------|------------------------|
| 环形缓冲（ring） | DMA 和网卡交接，属驱动 | 不是块设备 Buffer |
| `sk_buff` | 描述一帧的双向链表 | slab。协议栈上下层只改指针，不拷数据 |
| 套接字缓冲 | 应用 `read`/`write` 的那块；大小可按 fd 配 | 同样 slab |

`sk_buff` ≠ 套接字缓冲。一帧进来大致是 ring → skb → socket → 用户态；协议栈内部不按层复制。占用看 `/proc/slabinfo`。DPDK / PF_RING ZC 用 mmap 把 ring 直接映到用户态，省掉 skb 和协议栈。

## 协议栈谁在跑

不全是一个内核线程。软中断绑在每 CPU 的 `ksoftirqd/N` 上，还要硬中断、kworker、slab 一起干活。跟踪用 perf / systemtap / bcc。

## 65535 端口

连接 = 五元组。**客户端**单 IP 出站本地端口独占，最多约 65535（ab 也是多端口，再大要多机/多 IP）。**服务端**听固定端口，客户端 IP+端口可变，理论 2^48，实际卡在 fd、内存、协议栈，C10M 已经很难。Nginx 不给每个连接再 fork 随机端口，是客户端随机端口来连 80。

线上别顶着资源极限跑。

## MASQUERADE 思考题答案

端口相同也能工作，靠五元组 + conntrack，不必应用自己改端口。量大时：出口 IP 的端口会被改写所以端口成瓶颈，加上 conntrack、带宽、单点。
