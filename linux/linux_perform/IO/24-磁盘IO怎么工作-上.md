# 24 | Linux 磁盘 I/O 是怎么工作的（上）

原文：[time.geekbang.org/column/article/77010](https://time.geekbang.org/column/article/77010)

存储 I/O 栈三层：**文件系统层 → 通用块层 → 设备层**。通块层是核心：统一块设备接口，并对请求排队、排序、合并。

## 磁盘

| | HDD | SSD |
|--|-----|-----|
| 介质 | 盘片 + 磁头 | 电子元件 |
| 最小单位 | 扇区 512B | **页**（4KB/8KB），没有磁道 |
| 随机慢的原因 | 寻道 + 旋转 | 先擦再写 + 垃圾回收 |
| 连续快还因为 | 少寻道 | 可预读、少 GC |

同盘上随机都比连续慢。Kafka 一类用顺序写吃磁盘吞吐，就是这个道理。接口不同设备名不同：IDE=`hd*`，SCSI/SATA=`sd*`，多块按 a/b/c。分区再加数字：`sda1`。

架构：独立盘 / RAID（0 最快无冗余，1/5/10 有冗余）/ 网络存储。iSCSI 暴露的是**块设备**，不是 NAS。块设备有主/次设备号。

`select` **不能**用来等普通文件就绪：手册写明普通文件的读写/错误始终为 ready。

## 调度算法

```bash
cat /sys/block/sda/queue/scheduler
```

| 算法 | 特点 | 常见场景 |
|------|------|----------|
| NONE | 不做调度 | 虚拟机（调度交给宿主机）；看发行版 |
| NOOP | FIFO + 基本合并 | SSD |
| CFQ | 每进程一个队列，按时间片；可设 I/O 优先级 | 桌面、多媒体（很多发行版默认） |
| Deadline | 读/写分队列，到期优先 | 数据库等压力大的场景 |

MySQL 数据在机械盘上，noop 和 deadline 都可以；要用真实访问模式测，不要只跑合成 fio。

多线程读写同一盘上不同文件**可以**更快：中间有页缓存，块层会排序合并；阻塞 I/O 时各线程只堵自己那份，不会全员排队等同一次写。

## 缓存位置

- 文件访问：页缓存、inode 缓存、dentry 缓存 → 少打块设备
- 块设备：Buffer

性能跟 CPU/内存数量**不是线性**，测压环境不能按核数内存等比缩小当通过线。
