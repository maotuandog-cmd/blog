# GDB 使用说明 (三) 断点 / 观察点 / 控制执行

承接: (一) 原理 (二) 准备
本节聚焦: break / watch / next / step / continue / finish / until

================================================================
3.1 断点 (breakpoint) — 让程序停在指定位置
================================================================

断点 = 在某条指令上替换为 int3 (0xCC), CPU 触发 SIGTRAP 让 GDB 拿到控制权

----------------------------------------------------------------
3.1.1 按位置设断点
----------------------------------------------------------------
  break main                 main 函数入口
  break foo.c:42             源文件:行号
  break foo.c:42 if x > 10   条件断点 (仅 x > 10 时停)
  break *0x4005a6            绝对地址
  break +5                   当前行往后 5 行
  break -3                   当前行往前 3 行
  break foo()                函数名 (重载 C++ 用)

正则:
  rbreak .                   当前文件所有函数
  rbreak ^List_              以 "List_" 开头的所有函数

----------------------------------------------------------------
3.1.2 按函数入口设断点 (推荐起步)
----------------------------------------------------------------
  break my_function
  break my_function if i == 99     # 仅命中一次
  commands 1                       # 命中后自动执行的命令序列
    silent
    print i
    continue
  end

  # 取消 commands:
  commands 1
  end

----------------------------------------------------------------
3.1.3 临时断点 (命中一次后自动删除)
----------------------------------------------------------------
  tbreak main                   # 临时断点
  tbreak foo.c:42 if err == -1

----------------------------------------------------------------
3.1.4 跳过特定函数的断点 (skip)
----------------------------------------------------------------
  skip function strlen         # 跳过 strlen
  skip file uninteresting.c    # 整个文件都不进
  info skip                    # 查看规则

  # 跳过后, next/step 会把整个函数当一行跑过

----------------------------------------------------------------
3.1.5 断点编号管理
----------------------------------------------------------------
  info breakpoints
  # 别名: info b
  # 列: Num Type Disp Enb Address What
  # Num=1  HW breakpoint keep y   0x... in main at foo.c:42

  delete 1
  delete                        # 全删
  enable 1 2 3
  disable 1
  enable once 1                 # 命中一次后自动 disable
  enable delete 1              # 命中一次后自动 delete

================================================================
3.2 观察点 (watchpoint) — 数据变化时停下
================================================================

观察点监视内存地址变化, 需要硬件支持 (x86 都有)

----------------------------------------------------------------
3.2.1 三种观察点
----------------------------------------------------------------
  watch global_var            # 写入时停
  rwatch global_var           # 读取时停
  awatch global_var           # 读或写都停

  watch *(int*)0x601040       # 地址监视
  watch *(int*)&obj.field     # 结构体字段
  watch -l list.head          # 表达式作为左值

----------------------------------------------------------------
3.2.2 局部变量观察
----------------------------------------------------------------
  watch local_var
  # 作用域消失后 GDB 自动删除, 但用 -location 才能追踪移动的局部变量
  watch -l *(int*)0x7fff...   # 用地址而非名字

⚠️ 局部变量在栈上的地址每次调用都不同, 优先用名字

----------------------------------------------------------------
3.2.3 读取点 (rwatch) — 慢, 但能抓"谁读了我的数据"
----------------------------------------------------------------
  rwatch shared_counter
  # 命中即停

================================================================
3.3 控制执行
================================================================

----------------------------------------------------------------
3.3.1 推进 vs 步入 vs 步过
----------------------------------------------------------------
  next                         # 下一行 (不进函数)
  # 别名: n

  step                         # 下一行 (进函数)
  # 别名: s

  stepi                        # 下一条指令
  nexti                        # 下一条指令 (不进入 call)

  finish                       # 跑完当前函数, 停在外层调用
  until                        # 跑出当前循环 / 跑到指定行
  until 100                    # 跑到 line 100
  advance 100                  # 等价于 until 但用于绝对行

  continue                     # 跑到下一个断点 / 结束
  # 别名: c
  continue 100                 # 跳转到 line 100 (中间指令都会执行)

----------------------------------------------------------------
3.3.2 反向调试 (reverse debug)
----------------------------------------------------------------
  reverse-step                 # 后退一步 (进入函数)
  reverse-next                 # 后退一步 (不进入)
  reverse-continue             # 后退到上一个断点

⚠️ 需要 process record (慢, 占内存) 或硬件支持
⚠️ 反向调试不开源, 仅 GDB 内置支持

启用 record:
  target record-full           # 开始记录 (慢)
  reverse-step                 # 现在可用了
  target record-stop            # 停止记录

================================================================
3.4 信号触发停
----------------------------------------------------------------
  handle SIGINT stop print     # Ctrl-C 后 GDB 拿到控制权
  handle SIGSEGV stop print    # 段错误停下让你看
  handle SIGPIPE nostop noprint pass
  signal SIGUSR1               # 主动向 inferior 发信号

================================================================
3.5 条件断点 — 实战必备
================================================================

普通条件:
  break foo.c:42 if x > 100
  condition 1 x > 100          # 给已存在的 bp 1 加条件

命中计数:
  ignore 1 100                 # bp 1 跳过前 100 次命中

打印 + 继续 (不真正停下):
  break foo.c:42
  commands 1
    silent
    printf "i=%d sum=%d\n", i, sum
    continue
  end
  # "silent" 让 GDB 不显示 "Breakpoint 1, ..."

================================================================
3.6 捕获点 (catch) — 系统事件触发
================================================================

  catch syscall open           # 调用 open() 时停
  catch syscall write          # 调用 write() 时停
  catch fork                   # fork() 时停
  catch vfork                  # vfork() 时停
  catch exec                   # exec() 时停
  catch signal SIGSEGV         # 收到 SIGSEGV 时停
  catch throw                  # C++ throw 时停 (catch catch)
  catch catch                  # C++ catch 时停

  delete catch 1
  info catchpoints

================================================================
3.7 内存断点 (ranger-step) — 调试 malloc 链
================================================================
  ranger-step      # next 的变体, 跳过整个函数而非进入
  # 默认没开, 仅 record/replay 模式可用

================================================================
3.8 启动时自动断点
================================================================
  # 启动停在 main 而不是 _start
  set startup-with-shell off
  start                       # 等价于 b main; run
  starti                      # 停在第一条指令 (看汇编)

================================================================
3.9 实战模板: 调试启动失败
================================================================

(gdb) break _exit
(gdb) run
# 跑时崩了, 自动停下看 bt

(gdb) bt
# 看栈

(gdb) info registers
# 看 PC / SP / 通用寄存器

(gdb) disassemble $pc-32, $pc+32
# 看崩溃点附近的反汇编

================================================================
3.10 实战模板: 调试循环性能问题
================================================================

(gdb) break foo.c:100
(gdb) commands 1
  silent
  printf "iter=%d\n", iter
  continue
end
(gdb) continue
# 类似 printk, 不真正停下

================================================================
3.11 实战模板: 验证 fix 是否生效
----------------------------------------------------------------

改代码 → 重新编译 → 重新 attach (或 restart 程序)
gdb 没热重载功能; 全靠"改完重跑"循环

================================================================
3.12 断点持久化 (save-breakpoints)
----------------------------------------------------------------

(gdb) save breakpoints bp.gdb
# 把当前所有断点保存到文件
(gdb) source bp.gdb
# 下次启动时 source 恢复

================================================================
3.13 容易踩的坑
================================================================

1. 优化掉的变量
   -O2 下, "局部变量 i" 可能被优化成寄存器, print i 显示
   "<optimized out>"
   → 编译时加 -O0, 或 print $rdi 看寄存器

2. 行号错位
   -O2 下 line 50 实际可能是另一条指令
   → 改用 break *addr

3. 断点不命中
   - 函数被 static inline 编译器吃掉了
   - 函数在动态库里没加载 (用 share 命令)
   → nm -D | grep, 或 info sharedlibrary

4. 条件断点慢
   - 命中点 100M 次/秒, 条件表达式每次都求值
   → 用硬件观察点更便宜

5. SIGUSR1 被拦截
   见 2.3

6. next 不走预期路径
   - 当前行有多个语句 (a++; b++;)
   → 用 step 进同行的下一语句, 或 print 触发副作用

================================================================
术语表 (本章)
================================================================

  int3              x86 断点指令 (1 字节, 0xCC)
  HW breakpoint     硬件断点 (x86 DR0-DR3, 仅 4 个)
  SW breakpoint     软件断点 (替换指令)
  condition         断点的条件表达式
  commands         断点命中后自动执行的命令序列
  silent           在 commands 里, 不显示命中信息
  ranger-step      跳过整个函数
  reverse debug    反向执行
  record-full     GDB 录制执行 (支持反向)
  catch           捕获点 (syscall / signal / fork 等)
