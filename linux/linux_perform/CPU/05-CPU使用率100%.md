# 05 | 某个应用 CPU 使用率达到 100%，我该怎么办？

原文：[time.geekbang.org/column/article/70476](https://time.geekbang.org/column/article/70476)

## CPU 使用率怎么来的

Linux 用节拍率 **HZ**（看 `/boot/config-$(uname -r)` 里的 `CONFIG_HZ`）触发时钟中断，全局变量 **Jiffies** 累加。用户空间看到的是固定 **USER_HZ=100**（单位 10ms）。

数据源：`/proc/stat`（系统）、`/proc/[pid]/stat`（进程）。里面是**开机以来的累加节拍**，直接除出来没参考价值。工具都是 **间隔两次采样再作差**。

所以：`top` 默认约 3 秒平均，`ps` 默认是进程**整个生命周期**平均，两个 %CPU 对不上很正常。对比工具时间隔要一致。

## 各列含义（top / mpstat）

| 列 | 含义 | 高了先查 |
|----|------|----------|
| us | 用户态（不含 nice，含 guest） | 用户进程 |
| ni | nice 1–19 的低优先级用户态 | 低优先级进程 |
| sy | 内核态 | 内核线程 / 系统调用 |
| id | 空闲（不含 iowait） | — |
| wa | 等 I/O | 存储 / NFS |
| hi | 硬中断 | 中断处理 |
| si | 软中断 | 网络收发等 |
| st | 虚拟机被宿主机抢走 | 超卖 |
| guest | 跑虚拟机 | 宿主机 |

**CPU 使用率 = 非 idle 时间 / 总时间**（idle 不含 iowait）。

`top` 里进程 %CPU = 用户态 + 内核态（还含在就绪队列等待的部分）。按 `1` 可看每核。细分 us/sy 用 `pidstat`。

```bash
top                  # 按 1 看每核
pidstat 1 5          # %usr %system %wait %CPU
```

## 不要一上来就 GDB

GDB 会停进程，线上早期别用。先 **perf** 找热点函数，锁定后再线下调试。

```bash
perf top                  # 实时热点，看采样数够不够
perf top -g -p <pid>      # 调用链
perf record -g -- sleep 10
perf report
```

`Overhead` 是该符号占采样的比例；`[.]` 用户态，`[k]` 内核。采样太少则百分比没意义。

容器里 perf 常只看到地址：符号表在容器内。可 `perf record` 把 `perf.data` 拷进容器再 `perf report`。Java 用 `top -H` + `jstack` 对 nid。

## 案例：Nginx + PHP 只有 11 QPS

压测 `ab -c 10 -n 10000`，`top` 见 php-fpm 把两核 us 打到 98%+。`perf top -g -p <php-fpm>` 热点落到 `sqrt` / `add_function`。源码里测试循环没删：

```php
for ($i = 0; $i <= 1000000; $i++) {
  $x += sqrt($x);
}
```

删掉后 QPS 从 11 到 2200+。

套路：**top/pidstat 定位进程 → perf 定位函数 → 对照代码。**
