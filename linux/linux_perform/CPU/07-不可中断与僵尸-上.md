# 07 | 大量不可中断进程和僵尸进程（上）

原文：[time.geekbang.org/column/article/71064](https://time.geekbang.org/column/article/71064)

原理篇。案例操作在 [[08-不可中断与僵尸-下]]。

## 进程状态（top/ps 的 S 列）

| 状态 | 含义 |
|------|------|
| **R** | Running / Runnable，在跑或等 CPU |
| **D** | Disk Sleep，不可中断睡眠，多在等硬件 I/O |
| **Z** | Zombie，已退出，父进程没回收 |
| **S** | 可中断睡眠，等事件 |
| **I** | Idle，空闲的不可中断**内核线程**，**不抬高负载** |
| **T/t** | Stopped / Traced（SIGSTOP 或 gdb） |
| **X** | Dead，一般看不到 |

后缀常见：`s` 会话领导，`+` 前台进程组。

**D 不是「占着 CPU 不放」**，而是**不能被信号打断**（保护与硬件数据一致）。中断照样能发生，别的进程也能跑。短时间 D 可忽略；长时间大量 D → 查 I/O。

**Z**：父进程应用 `wait/waitpid` 或处理 `SIGCHLD`。短暂僵尸正常；父进程一直不收，PID 会耗尽，新进程创建失败。父进程退出后由 init/systemd 收。

## 案例现象（先记下，下讲拆）

`docker run --privileged --name=app -itd feisky/app:iowait`

- load 升到约等于核数  
- Tasks 里 **zombie 不断增加**  
- **wa** 很高（60%～90%），us/sy 很低  
- 有多个 **D** 状态的 `/app`

新工具：`dstat`（把 vmstat/iostat/ifstat 合在一起看）。

CentOS 上镜像可能打不出 iowait：IO 不够大或设备路径不对，需 `--privileged` 并指定块设备；也可用 cgroup 限制 iops 来模拟。
