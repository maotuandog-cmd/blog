# 21 | 如何「快准狠」找到系统内存问题？

原文：[time.geekbang.org/column/article/76460](https://time.geekbang.org/column/article/76460)

内存篇总复习。不要把工具全跑一遍。目标：热点数据留在内存里，少缺页、少 Swap。

## 指标清单

**系统**

| 指标 | 注意 |
|------|------|
| used / free | 字面占用和空闲 |
| shared | 实际是 tmpfs，也是一种缓存 |
| available | 新进程能用的上限 = free + 可回收缓存 |
| Cache | 文件页缓存 + 可回收 Slab |
| Buffer | 磁盘块缓冲 |

**进程**（`top` / `ps` 给出的数和教材定义可能不完全一样）

| 指标 | 教材定义 | 工具里常见情况 |
|------|----------|----------------|
| VIRT | 申请过的虚拟内存，没给物理页也算 | 高通常无害 |
| RES / 常驻 | 实际物理内存，不含 Swap、共享 | **RSS 往往会把共享也算进去**，以工具说明为准 |
| SHR | 真共享 + 代码段 + 动态库 | 不要跨进程相加 |
| Swap | 换出去的 | `/proc/<pid>/status` 的 VmSwap |

**缺页**

- **次缺页**：物理内存里就能补上
- **主缺页**：要磁盘（含 Swap）—— 这个升高，访问会明显变慢

**Swap**：已用/剩余、si/so（每秒换入换出量）

## 先跑这几个

```bash
free -h
top          # 按 M 按内存排
vmstat 1     # free/buff/cache、si/so
pidstat -r 1
```

再按现象分支：

```text
free 显示 cache 很大
  → vmstat/sar 看还在不在涨
  → 还在涨：cachetop / slabtop 找谁在用

available 不够
  → 先排除 cache/buffer
  → pidstat/top 找大户 → pmap 看地址空间

vmstat 里 used 持续涨、cache 不动
  → memleak（老内核用 valgrind）看泄漏栈

si/so 或 Swap 占用升
  → zoneinfo 对水位
  → 进程 VmSwap / smem
  → 查 NUMA、swappiness
```

bcc 要新内核。替代：泄漏用 valgrind，动态跟踪用 systemtap。缓慢涨 Swap 靠监控看趋势，`sar`/`vmstat` 一秒采样可能看不见每天几十 MB。

## 优化方向

1. 能关 Swap 就关；必须开就降 swappiness
2. 少动态分配：内存池、大页
3. 用好 Cache/Buffer；热点再加进程内缓存或 Redis
4. cgroups 限制进程内存，防一个家伙吃光
5. 核心进程调低 `oom_adj`，尽量别被 OOM 杀掉
