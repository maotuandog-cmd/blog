# 01 · 集群安装选型

> 承接 [[00-总览与学习路线]]。本专题**主路径 = kubeadm**。  
> 官方对比入口：[Production environment](https://kubernetes.io/docs/setup/production-environment/) · [kubeadm overview](https://kubernetes.io/docs/setup/production-environment/tools/kubeadm/)

## 1. 三种常见路径

| 工具 | 适合 | 不适合 | 本专题定位 |
|------|------|--------|------------|
| **kubeadm** | 裸金属/VM、要贴近上游、可升级可审计 | 想「一条命令全包运维」 | **主线** |
| **kind** | 本机多节点实验、CI | 当生产 | 实验辅线（见容器网络 06） |
| **k3s** | 边缘、极简单二进制、Homelab 省事 | 要完整上游组件清单教学 | 可选，本文不展开安装 |

托管云（EKS/GKE/AKS）控制面由厂商管：本目录命令仍适用应用层；节点/CNI 跟云文档走。

## 2. 为何主选 kubeadm

- 官方维护的**引导工具**：init / join / upgrade / reset 生命周期完整  
- 装出来的是标准控制面（kube-apiserver、scheduler、controller-manager、etcd）  
- 易与 Ansible/Terraform 组合；通过一致性测试的常见底座  
- 学完后换托管或发行版，概念可迁移

## 3. 本期集群形态（默认假设）

```text
1 × 控制面（可叠 etcd）  +  N × worker
Ubuntu 22.04/24.04 或同类 deb
containerd
CNI：装完 init 再装（Cilium / Calico / Flannel）
单控制面先跑通；HA 需 init 时带 --control-plane-endpoint
```

硬件下限（官方 Installing kubeadm）：

- 每机内存 ≥ **2 GiB**（控制面建议更多）  
- 控制面 CPU ≥ **2**  
- 节点间**全互通**；hostname / MAC / `product_uuid` 唯一  
- 端口按官方 [Ports and Protocols](https://kubernetes.io/docs/reference/networking/ports-and-protocols/) 放行  

公网拼节点：先 VPN/WireGuard，再 kubeadm（同容器网络约定）。

## 4. 选型检查清单

- [ ] 用途是学习/Homelab/小生产，而不是「只要能跑演示」→ kubeadm  
- [ ] 只要本机跟包、不准备长期节点 → kind 即可，不必上 kubeadm  
- [ ] 已选定 K8s **minor**（如 1.33），后续包源、文档页、CNI 版本对齐  
- [ ] 已选定 CNI 与 `--pod-network-cidr`（见 [[容器网络/08-CNI三选一安装与配置]]）
